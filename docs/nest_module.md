# C++-астроцит и SIC-сеть в NEST 3.10

Параметр `allow_ip3_extrapolation=True` позволяет продолжить крайние
аффинные области при IP3 > 1.3 мкМ. По умолчанию он выключен.
Это экстраполяция поля в преобразованных координатах; физические границы
h и совпадение SIC нужно оценивать отдельно.
[Опыт с исходным сетевым входом](../results/network_extrapolation/REPORT.md).

Допустимы положительные упорядоченные IP3-пороги выше 1.3 мкМ;
для работы в этой области требуется `allow_ip3_extrapolation=True`.
[Дополнительный верхний порог](../results/high_ip3_hinge/REPORT.md)
подобран отдельно от исходных моделей и не меняет их значения по умолчанию.

Загружаемый модуль `astrocyte_lr_pwa` реализует входные спайки, IP3,
решатель и генерацию SIC внутри NEST. Ток доставляется штатным
`sic_connection` в `aeif_cond_alpha_astro`. Python собирает сеть и читает
результаты после прогона. [Результаты](../results/nest_benchmark/REPORT.md).

## Кандидаты

- AM: `models/server_candidates/AM_sqrt_tails__cube.json`, четыре C-области,
  три I-слоя; координаты sqrt_tails(C), h³, I.
- FM: `models/phase_shape_candidates/FM_width_soft_candidate.json`, восемь
  C-областей; аффинно нормированные физические C,h и точный I.

Коэффициенты не подбирались заново. Пути и SHA256 записаны в benchmark.json.
Обе стороны стартуют из одинакового физического равновесия канонической LR:
I=.2 для AM, I=.45 для FM. У AM это не собственный точный покой PWA,
поэтому сравнение включает его начальную релаксацию.

## Сборка без root

```bash
cd /workspace/PWL-NEST

.venv/bin/python -m pip install --no-build-isolation -e '.[nest]'
# При установленных системных Boost/libltdl/GSL dev-заголовках:

# Либо извлечь проверенные SHA256 Debian-пакеты в .cache, без установки в ОС:

```

Нужны Linux x86_64, g++ с C++20, `nm`; для распаковки также `dpkg-deb`.
Скрипт берёт заголовки из установленного NEST 3.10, определяет string ABI
и собирает `.build/pwl_astro_module.so`, `.build/solver_timing.so`.
У PyPI wheel `nest-config` содержит пути машины сборки; они не используются
как локальные include/lib пути. GSL берётся из того же wheel; Debian-пакеты
используются только как заголовки. Можно указать свой `--dev-include PATH`.

## Сеть и единицы

```python
import nest
from pwl_nest.nest_adapter import build_network, load_candidate

model, provenance = load_candidate('FM')
initial = model.metadata['exact_rest_constraint']
protocol = dict(tau=20., baseline=.45, jumps=[[20., .7]])
astro, neurons, meters = build_network(
    'FM', model, initial, protocol, population=64,
    resolution_ms=1., record_interval_ms=10., delay_ms=10.)
nest.Simulate(220000.)
calcium = meters[0].events
delivered_sic = meters[1].events['I_SIC']
```

`kind='lr'` строит контрольную сеть. Каждый `build_network` начинает с
`ResetKernel`. Контроль использует исходные скорости NEST, `Km_SERCA=.1`
для AM либо `.05` для FM. Времена протокола — секунды, времена NEST — мс.
Параметры физической и латентной координат преобразует Python-адаптер;
для прямого низкоуровневого Create состояние PWA задаётся через u,v,IP3.

Детерминированные `spike_generator` передают одинаковые входы всей популяции.
`delta_IP3=1`; вес спайкового соединения равен нужному скачку IP3. Генератор
отправляет спайк на одну задержку раньше желаемого скачка. Это учитывает
соглашение штатной LR: вход добавляется после интегрирования текущего шага.
Вес неотрицателен; выход IP3 из обученного [0,1.3] вызывает ошибку PWA.

Каждый астроцит соединён со своим AEIF весом SIC=1. У обоих астроцитов
SIC_scale=1, SIC_th=.19669 μM. Ток равен `log((C-.19669)*1000)` при аргументе
>1, иначе 0. Проверяется именно `I_SIC` целевого нейрона с задержкой.
Рекуррентных связей нет. Мультиметры пишут один репрезентативный астроцит
и нейрон; основные замеры скорости идут без мультиметров.

## Решатель

`native/pwa_step.h` использует матричную экспоненту 4×4 существующего
`native/pwa_event.cpp`. Пропагатор полного NEST-шага каждого региона кешируется
в Prepare; обычный шаг — умножение матрицы на вектор. C-пересечения уточняются
бисекцией по региональному потоку; время пересечения I-порога — логарифмом.
Скачок I сохраняет u,v. Обратные координаты нужны для выдачи C,h и SIC.
Clipping состояния PWA не применяется.

Это аналитический региональный решатель внутри шагового планировщика NEST;
глобальные NEST-тики не пропускаются. Bracketing C-пересечений проверяет
конец шага. Глобальной сертификации первого выхода, касаний и пересечения
с возвратом за один тик нет. Проверка включает деление тика пополам при
сохранённой физической задержке соединений. Наклонные C-пороги, смешение C–h,
произвольные координаты и CurrentEvent в этот адаптер не входят.

## Измерения и воспроизведение

Разделены три режима: астроциты в NEST; полная SIC-сеть с нейронами;
изолированные C++-ядра без SIC, нейронов и планировщика. В последнем случае
тот же Stepper сравнивается с GSL RKF45 и abs tolerance=1e-3, как у штатной
NEST LR. Изолированный LR — отдельная алгебраически эквивалентная реализация
RHS, а не инструментирование бинарного тела штатной модели. Терминальные
состояния обоих ядер сверены с реальными NEST-моделями.

Основной показатель — `nest.Run` двух реальных сетей. Build, Prepare и
чтение результатов записываются отдельно. Изолированный solve не включает
аллокации и подготовку кеша; эти затраты также записаны. Для короткого
запуска полную стоимость надо считать вместе с Prepare.

Один поток, один исключённый прогрев, три повтора NEST и чередование LR/PWA.
Основной timing: 120 с, шаг 10 мс, популяции 1/64/256. Отдельный sweep:
шаг .1/1/10 мс, 64 элемента, 60 с. У isolated_solver основной таблицы
три повтора без отдельного прогрева; sweep исключает прогрев также для него.

Пять входов на case: одиночные скачки tau20/100/180, периодическая и
нерегулярная последовательности. Нерегулярные времена заранее округлены
на общую сетку .05 с, seed=20261021. Ошибка SIC измеряется без фазового
выравнивания. Результаты не используются для нового подбора.
Timing использует редкие взвешенные спайки, эквивалентные заданным скачкам
IP3; пропускная способность плотного спайкового потока отдельно не измерялась.
