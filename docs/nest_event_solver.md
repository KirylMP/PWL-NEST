# Аналитическое событийное ядро для PWA-астроцита

## Что сделано

Добавлено C++-ядро для трёхмерной PWA-модели с вертикальными порогами по
кальцию. Внутри региона оно распространяет аффинное состояние через
масштабированную матричную экспоненту 4×4. IP₃ релаксирует экспоненциально;
скачки IP₃ применяются как мгновенные события без изменения C и h. Пересечения
C-порогов сначала локализуются коротким bracket-интервалом, затем уточняются
бисекцией по точному потоку текущего региона.

Python-обёртка — `src/pwl_nest/event_solver.py`, реализация —
`native/pwa_event.cpp`, сравнение — `scripts/benchmark_event_solver.py`.
Сборка `.build/pwa_event.so` добавлена в `scripts/setup.sh`.

## Сравнение

Проверена модель [FM_width_soft_candidate](../models/phase_shape_candidates/FM_width_soft_candidate.json),
восемь регионов. Все три расчёта начинались из одного точного равновесия LR
при I=.45 μM и использовали одинаковые входные скачки. DOP853 с шагом выдачи
.005 с проверяет численную точность на плотной сетке; событийный C++ возвращает
состояние каждые .05 с. Траектории сравнивались на общей сетке.

| Вход | Пики LR / PWA-event | RMSE C: PWA-event против LR, μM | RMSE C: PWA-event против PWA-DOP853, μM | Время C++ / LR-DOP853, с |
|---|---:|---:|---:|---:|
| Один скачок, τ=20 | 2 / 2 | 0.0657 | 1.1×10⁻¹⁰ | 0.0096 / 3.25 |
| Один скачок, τ=100 | 9 / 9 | 0.1871 | 2.4×10⁻⁹ | 0.0128 / 5.04 |
| Один скачок, τ=180 | 17 / 17 | 0.2984 | 2.9×10⁻⁹ | 0.0207 / 10.81 |
| Пять периодических скачков | 5 / 5 | 0.1903 | 2.3×10⁻¹⁰ | 0.0093 / 3.96 |
| Нерегулярные скачки, τ=22 | 8 / 8 | 0.2391 | 2.0×10⁻⁶ | 0.0135 / 6.05 |

На нерегулярном входе уменьшение scan_dt с .02 до .005 с изменило событийную
траекторию максимум на 3.8×10⁻¹¹ μM. Несколько сотен региональных пересечений
локализуются за 0.01–0.02 с на этих траекториях.

Событийный поток хорошо воспроизводит **ту же PWA-модель**, что подтверждает
корректность распространения и пересечений. При этом RMSE PWA относительно
канонической Li–Rinzel доходит до .30 μM на длинном спаде. Это ошибка самой
аппроксимации PWA; событийный интегратор её не устраняет. Числа времени —
одиночный локальный запуск против Python/SciPy DOP853, а не benchmark против
реального NEST-решателя; по ним нельзя заявлять ускорение в NEST.

Воспроизведение:

```sh
bash scripts/setup.sh
PYTHONPATH=src:scripts OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  .venv/bin/python scripts/benchmark_event_solver.py \
  --output results/nest_event_solver/benchmark.json --output-dt .05 --scan-dt .02
PYTHONPATH=src .venv/bin/python -m unittest tests.test_event_solver -v
```

Полная таблица, timing и диагностики сохранены в
[`results/nest_event_solver/benchmark.json`](../results/nest_event_solver/benchmark.json).

## Граница текущего результата

Это событийное C++-ядро, но пока не загружаемый NEST-модуль
`astrocyte_lr_pwa`. В окружении нет `nest`, `nest-config` и заголовков NEST;
TCP-доступ не настроен. Поэтому не собран и не запускался сам NEST, а штатный
NEST `astrocyte_lr_1994` ещё не использован как baseline. Пока не подключены
интерфейс событий NEST, штатная выдача непрерывного SIC и измерение времени
в NEST-популяции.

Ядро принимает только вертикальные C-пороги, без нелинейных координат, смешения
C–h, наклонных C-порогов и I-порогов. Оно ограничено текущим FM-кандидатом;
для другой геометрии нужен общий поиск первого выхода. Следующий шаг NEST —
собрать адаптер под конкретную версию NEST и перенести существующий
`astrocyte_lr_1994`-интерфейс вместе с его SIC-параметрами и правилами доставки
спайков; затем повторить эти протоколы уже в NEST.
