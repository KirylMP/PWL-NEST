# Строгая 3D PWA: первая идентификация

## Выбранный класс

X=(C,h,I), физические C и I в мкМ, h безразмерна, время в секундах.
Поле каждого тетраэдра: Xdot=A_j X+b_j, с постоянными коэффициентами
при заданных tau,I_b. Третья строка во всех регионах точно равна
(0,0,-1/tau), b_I=I_b/tau. Нет произведений C*I или h*I, степеней IP3,
преобразования состояния либо пересчёта кальциевых коэффициентов по текущему I.

Для каждого узла общей сетки хранятся два параметра: Cdot,hdot. Внутри
тетраэдра интерполируется **полное** двухкомпонентное поле, а не отдельные
биохимические множители. Одинаковые значения в общих вершинах гарантируют
совпадение аффинных следов на общих треугольных гранях. Третья компонента
совпадает по определению. Разбиение Freudenthal каждой прямоугольной ячейки
на шесть тетраэдров использует один порядок глобальных координат и является
согласованным на гранях соседних ячеек.

Важно: трилинейная интерполяция на прямоугольниках была бы непрерывной, но
содержала бы произведения координат и не удовлетворяла бы требованию аффинности.
Поэтому здесь именно симплициальная кусочно-линейная интерполяция.

## Почему не просто кальциевые полосы

Непрерывность соседних полей через плоскость n^T X=d требует
A_+-A_-=u*n^T, b_+-b_-=-u*d. Для параллельных C-порогов это позволяет
менять только столбец C и соответствующую константу; коэффициенты при h,I
остаются общими. Исходный класс legacy с независимо меняющимися mu(I),k(I)
не переносится в строгую 3D PWA. Тетраэдры — первая допустимая геометрия,
дающая свободу приближать полное поле. Её эффективность ещё не установлена.

## Эвристика геометрии

Из `lr_spectral.py` архива AM_two_movable_thresholds перенесён принцип:
найти равновесную кривую исходной Li–Rinzel и её спектральные ориентиры
trace=0 при det>0, det=0 и trace^2-4det=0. Реализация пересчитывает ориентиры
из уравнений для K_ER=.1 (AM) и .05 (FM), не копирует fitted legacy коэффициенты.
Все три координаты ориентиров добавляются в узлы C,h,I.
Это ориентиры **исходной** модели, не доказанные бифуркации PWA.
Спектральное сканирование по 1001 точке не является строгой сертификацией.

Дополнительная геометрическая сетка:
- C: логарифмические узлы [.005,.15] для нелинейной малокальциевой области,
  затем равномерные до C_max=2/1.185;
- h: [0,1], I: [0,1.3], равномерные вспомогательные узлы;
- refined: все интервалы делятся пополам, до просмотра holdout-результатов.

Первый эксперимент намеренно использует плотный reference-класс. Это не
кандидат на минимальную сложность или уже эффективную реализацию в NEST.
Размер сетки, число областей и свободных параметров записываются для каждого
кандидата; дальнейшая задача — адаптивное уменьшение при ограничениях на динамику.

## Подбор параметров

Сравниваются interpolation (значения LR в вершинах без оптимизации) и fit.
Для fit совместно подбираются значения полного Cdot,hdot в общих вершинах:
взвешенный линейный least squares по трём случайным точкам каждой ячейки,
плюс точки **только обучающих** LR-траекторий (вес 8), плюс ridge=.25
к исходным узловым значениям. Seed=20261020. Каждая компонента решается
независимо, но использует общую пространственную базу и геометрию.
IP3-строка не подбирается. Это первая идентификация поля; непосредственная
нелинейная оптимизация параметров по rollout и бифуркациям ещё не реализована.

Значения на всех границах физической коробки закреплены по LR. Поэтому
Cdot>=0 на C=0, Cdot<=0 на C=C_max, hdot>=0 на h=0, hdot<=0 на h=1.
Аффинность граней сохраняет эти неравенства между узлами; непрерывное поле
локально липшицево. Для I_b в [0,1.3] это даёт положительную инвариантность
коробки для точного непрерывного потока. Допустимы только IP3-скачки внутри
диапазона. Это свойство конструкции не означает произвольную точность
численного решателя или эквивалентность всей области реальному астроциту.

## Автономные и динамические испытания

Все сравнения стартуют из одинаковых **физических** (C,h,I).
Обучающие входы заданы в `scripts/fit_strict.py`: четыре фиксированных IP3,
два экспоненциальных спада tau=20,100 с. Выбор из coarse/refined ×
interpolation/fit — по заранее определённому среднему score этих шести испытаний.
Автономный score: (макс. ошибка экстремумов/.02)^2 + (ошибка периода/1с)^2.
Если оба расчёта покоятся, период не штрафуется; если цикл не разрешён в одном
из них, добавляется 100. Динамический score: (RMSE_C/.02)^2.
Это технические масштабы выбора, не ослабленный acceptance protocol legacy.

Holdout не участвует в подгонке или выборе: пять других фиксированных IP3,
спады tau=2,50 с, периодические и нерегулярные IP3-скачки с прекращением входа.
Список полностью сохраняется в JSON. Исторические значения IP3 из архивов
не являются слепым внешним экспериментом. Есть отдельная случайная проверка
поля (seed=319), также не используемая для выбора модели.

В DOP853 для численной проверки используются rtol=2e-7,atol=2e-9,max_step=.5 с.
Промежуточные RK trial stages могут выходить из коробки; для них допускается
аффинное продолжение граничного участка. Принятые выходные состояния
проверяются на выход из коробки; публичный evaluator запрещает экстраполяцию.
Это техника численной валидации, а не изменение модели или clipping состояния.

Период оценивается по последним 400 с, нужны как минимум четыре пика и
согласованные амплитуды половин окна. Неразрешённый/медленно сходящийся
режим явно обозначается unresolved. Близкие к границе режимы требуют
отдельного длинного прогона и continuation; краткий пилот не определяет бифуркацию.

## Аналитический поток и скачки

На каждом участке используется exp(t*M), M=[[A,b],[0,0]]. Это работает при
вырожденной A и вещественном либо комплексном спектре. I(t) автоматически
равен I_b+(I0-I_b)*exp(-t/tau), независимо от сетки и подгонки.
`regional_flow` намеренно не распространяет состояние через неизвестную границу.
Первый выход должен локализоваться отдельно; полный событийный решатель —
следующий этап. Траектории этого эксперимента вычисляет независимый DOP853
для проверки динамики самой PWA, не для заявления об аналитическом ускорении.

В момент входа C,h сохраняются, I+=DeltaI. После скачка выбирается регион
новой точки. Никаких преобразованных скрытых координат пересчитывать не надо.
`protocols.simulate` сохраняет состояния до и после каждого скачка.

## Воспроизведение

Из /workspace/PWL-NEST:

```bash
bash scripts/setup.sh
OPENBLAS_NUM_THREADS=1 .venv/bin/python scripts/fit_strict.py
.venv/bin/python -m unittest discover -s tests -v
```

Полный эксперимент сохраняет `models/strict_pwa/{AM,FM}.npz`, все четыре
кандидата каждой модели, параметры и результаты в `results/strict_pwa`.
`--quick` — только отладочный smoke; результаты отделены в каталоги
`strict_pwa_smoke`. Для воспроизведения исследовательских результатов
запускать без этого флага.

Не выполнены этим экспериментом: неустойчивые циклы, сертифицированные
бифуркационные границы, полный первый выход/касания в событийном решателе,
SIC, строгий C++ решатель и benchmark NEST. Ускорение и полное соответствие
блюпринту по динамическим критериям здесь не заявляются.
