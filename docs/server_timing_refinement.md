# Продолжение с кандидатами лабораторного сервера

Исходные файлы сохранены в `models/server_candidates/` без изменений.
Их происхождение, SHA256 и независимый повторный расчёт исходного критерия:
[`results/server_candidates`](../results/server_candidates/README.md).
Полная присланная сводка и двумерные таблицы:
[`results/server_coordinate_grid`](../results/server_coordinate_grid/README.md).

В модели AM `sqrt_tails + cube` совпали четыре тестовых числа пиков.
У `sqrt_tails + log` меньше обучающий loss, но пропущен последний пик при tau=65.
Для FM минимум исходного train loss имеет `identity + identity`; поздние пики
при экспоненциальном спаде входа всё ещё смещаются по времени.

## Новый критерий — отдельный опыт

К прежнему критерию добавлен остаток для **абсолютного времени каждого пика**:
`(t_candidate[k] - t_LR[k]) / 1 s`. Пики берутся в хронологическом порядке,
без сдвига траекторий и без индивидуального фазового выравнивания. При отсутствии
пика его компонент равен 25; лишние пики по-прежнему штрафуются прежним
остатком числа пиков. Фиксированная длина остатка определяется числом пиков LR.
Все прежние штрафы, обучение на автономных режимах и собственном покое сохранены.

После обнаружения максимума по отсчётам его время уточняется вершиной параболы
по трём соседним точкам. Это делает временной остаток менее ступенчатым для
оптимизатора; это не полиномиальное изменение уравнений модели. При невозможном
положении вершины остаётся исходное время отсчёта. Используются настоящие времена
соседних точек, включая неравномерную сетку около событий.

Не меняются класс уравнений, число областей, типы спектров, экспоненциальное I,
правила обратного преобразования или инициализация. Подбираются прежние
коэффициенты и упорядоченные C-пороги. Начальная точка определяется устойчивым
равновесием кандидата, затем 20 с задержки перед первым входом. C/h не обрезаются.

Новый train loss численно **не сравним** со старым loss: добавлены компоненты.
В каждом опыте исходный серверный кандидат сначала оценивается новым критерием.
Продолжение выбирается только при уменьшении независимо пересчитанного DOP853
нового train loss. Если попытки ухудшили его, сохраняется исходный кандидат.
Внутренний подбор использует прежние native-решатели.

## Проверочные входы

Четыре прежних теста сохраняются как диагностика; после просмотра сводки они
не считаются новыми независимыми данными. Дополнительно заранее заданы:

- импульсы с tau=13,35,80,140, с тем же фоном и амплитудой, что в первом опыте;
- новый нерегулярный вход с tau=17, seed=20261023 и варьируемыми амплитудами;
- каждый вход начинается из собственного покоя, со скачком только I в t=20 с.

Оба набора вычисляются после выбора по обучению и не участвуют в выборе.
Файл `summary.json` хранит отдельно baseline/selected и previous_tests/new_tests.

## Воспроизведение

Из корня репозитория, с установленными зависимостями и собранными native-модулями
(как для первого запуска):

```bash
PYTHONPATH=src:scripts OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  .venv/bin/python scripts/refine_server_candidates.py \
  --output runs/fm-absolute-timing --budget 1500 --restarts 3

.venv/bin/python scripts/plot_timing_refinement.py runs/fm-absolute-timing
```

Если Python находится в соседней лабораторной `.venv`, замените путь к Python.
Можно передать `--reference-cache /path/to/old/run/cache`; иначе исходные LR
траектории будут вычислены заново. Для AM используйте, например,
`--models AM_sqrt_tails__cube AM_sqrt_tails__log`. По умолчанию подбирается FM.
`--restarts 0` выполняет только сравнительную диагностику исходного кандидата.

Выберите **новый каталог или существующий пустой** для каждого отдельного опыта; автоматического
продолжения этой целевой серии пока нет. Все попытки, checkpoints и кандидаты
сохраняются. Полный аналитический поиск первого выхода и общая приёмка blueprint
не добавляются этой сменой критерия.

Если подбор завершился, но построение итоговой диагностики было прервано,
`--replay-trials` с теми же параметрами заново проверит сохранённых кандидатов
по обучению и завершит диагностику без повторной оптимизации. Исходные
`result.json` остаются, повторные оценки записываются в `replay_result.json`.
