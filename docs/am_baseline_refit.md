# Дополнительный подбор AM по исходному критерию

Опыт продолжает два замороженных серверных кандидата: sqrt_tails(C)+h³
и sqrt_tails(C)+ln(h). Новые модели и все попытки находятся отдельно от
оригиналов: [results/am_baseline_refit](../results/am_baseline_refit/REPORT.md).

Сохраняются 21 активный параметр, четыре C-полосы, два I-узла (.35,.64)
и 12 областей. Подбираются прежние коэффициенты, упорядоченные C-пороги
и коэффициенты I-hinges. Типы региональных спектров, координатные нормировки,
точная экспонента IP3 и отсутствие clipping остаются прежними.

Используется исходный `RestObjective` из `overnight_coordinate_grid.py`:
автономные режимы и спектральные якоря; собственный устойчивый покой при
I=.3; скачок .35 в t=20 с с tau20/100; периодические скачки .16.
Критерий учитывает высоты и ширины пиков, интервалы, первую задержку,
число пиков и слабую поточечную ошибку. Абсолютное время каждого пика
и SIC в остаток не добавляются. Начальные C,h не оптимизируются отдельно.

Полевая инициализация заново строится исключительно по фиксированным
и динамическим обучающим траекториям. Старые тесты исторически известны;
устранение утечки из новой инициализации не делает прошлую историю seed
независимой задним числом.

## Численная проверка

На первой паре продолжений h³ ускоренный RK4/.005 давал ложный выигрыш:
ошибка C около 2e-7 μM меняла число обнаруженных пиков из-за почти точного
совпадения prominence с порогом .02. Независимый DOP853 отверг эту точку.
Сами исходные траектории при этом близки; большой скачок loss связан
с дискретным счётчиком и сопоставлением пиков, а не большим расхождением C.
Аудит: `initial_numerical_audit.json`.

Следующая пара продолжений на ветвь использует RK4/.001 и локальный Powell
в окне ±.01*max(1,abs(parameter)), пересечённом с прежними глобальными bounds.
Определение остатка, пороги пиков и допустимый класс не менялись. Все
кандидаты проходят полный независимый DOP replay обучения. Выбор делается
по этому train-loss, включая возможность оставить исходную модель.

Уточнение статической части: native attractor-статистики могут отличаться
от статистик полного 1600-секундного окна. Поэтому добавлен `--flow-helper`:
тот же исходный остаток вычисляется по полным траекториям, полученным
кешированным аналитическим потоком из NEST-решателя. На обоих исходных
кандидатах согласование с DOP853 проверено в flow_helper_audit.json.
Проведено ещё по одному продолжению на ветвь, то есть пять всего.

## Запуск

```bash
export PYTHONPATH=src:scripts OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1
export MPLCONFIGDIR=/tmp/nest-matplotlib XDG_CACHE_HOME=/tmp
.venv/bin/python scripts/refine_server_candidates.py \
  --models AM_sqrt_tails__cube --base-objective \
  --output results/am_baseline_refit/cube \
  --budget 1500 --restarts 2 --seed 20261024
.venv/bin/python scripts/refine_server_candidates.py \
  --models AM_sqrt_tails__cube --base-objective \
  --output results/am_baseline_refit/refined/cube \
  --budget 1500 --restarts 2 --seed 20261025 \
  --native-maxdt .001 --powell-radius .01
# Полные фиксированные траектории и аналитический поток, исходный остаток:
.venv/bin/python scripts/refine_server_candidates.py \
  --models AM_sqrt_tails__cube --base-objective --flow-helper \
  --output results/am_baseline_refit/flow/cube \
  --budget 1500 --restarts 1 --seed 20261026 \
  --native-maxdt .02 --powell-radius .01
# Аналогичные два запуска для AM_sqrt_tails__log, в отдельных каталогах log.
.venv/bin/python scripts/evaluate_am_baseline_refit.py
```

Число 1500 ограничивает вызовы остатка на каждую из двух LS-стадий и Powell.
Ранние остановки и фактические числа оценок сохраняются. Исходный режим
скрипта с дополнительными абсолютными временами пиков остаётся доступен
без `--base-objective`; новые настройки по умолчанию сохраняют прежний шаг
и глобальные bounds Powell.

## Проверка SIC

После train-выбора обе исходные модели и оба продолжения прогоняются в NEST.
Новые входы заданы заранее в evaluation_plan.json: tau9/29/58/115 и
нерегулярный вход с seed=20261024. Начало — из собственного покоя, I=.3.
Отдельно повторяется известный NEST stress-набор при фоне .2 и скачке .7,
из общего начального состояния LR. Он не добавляется в обучение.

Измеряется доставленный I_SIC целевого `aeif_cond_alpha_astro`, а не
только readout C. Ошибки не выравниваются по фазе. SIC-диагностики не
перевыбирают победителя по обучению. Если они ухудшатся, это сохраняется
в отчёте. Выбранная модель записывается отдельно; исходные модели и default
NEST-кандидат не заменяются молча. Скорость в этом опыте не переизмеряется.
