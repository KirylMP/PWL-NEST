# AM fixed-fold fit under reset stress

Search the existing continuous three-zone AM model without a new threshold or clipping. Use prior AM fits 465, 2311, 3080 and 3420 as initial fields. Preserve the zero-input equilibrium, both equilibrium crossing inputs, the upper neutral cycle input and the stable lower / unstable focus middle / stable focus upper constraints. The previous amplitude, period and normalized aligned-waveform objective is unchanged.

Physicality is a hard *finite numerical* constraint, not an additional weighted loss term. Start at the candidate's specified rest state, integrate for 80 s at I=0.2 µM. From this state separately integrate at I=0.75, 1.0 and 1.2 µM, and at t=20, 40, 60 and 80 s after each switch branch into I=0 for 30 s. Check the minimum calcium over baseline, high-input and every reset trajectory, including numerical turning points. The test explores selected reachable states and phases; it is neither a general positivity certificate nor a proof of a worst-case input. A model rejected by the finite search is not proof that no feasible model exists. I=1.2 is a chosen stress level, not a claimed physiological maximum.

Each start runs two stages. First, Nelder–Mead searches for a model meeting the stress condition; its feasibility objective is not the reported fitting loss. The first feasible field with all seven training cycles seeds SLSQP, which minimizes the original cycle loss while imposing min_C >= 0 as an inequality constraint. Only feasible checkpoints are eligible. Nonlinear fold matching, finite starting phases and numerical integration can fail; report failure and convergence separately. Four holdout cycles are computed after fitting, not used to select the training candidate.

The batch starts 16 isolated processes by default, cycles through the four seeds with randomized normalized-coefficient jitter, and records separate logs and candidates. Existing incomplete directories are retained, never overwritten. One process may use one CPU thread. The exact finite bounds, solver budgets, tolerances, starting seed and field hashes are saved in the output. This exploratory search can return no feasible candidates or be slow; it is not a global optimizer.
