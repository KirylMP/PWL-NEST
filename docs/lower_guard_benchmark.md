# Lower calcium guard: existing fitted fields

For selected AM 465, AFM 800 and FM 474, add `dC/dt += k max(0, Cg-C)` with `Cg = 0.025 µM`, `k = 100 s^-1` by inserting one continuous affine zone. Leave `dq/dt` unchanged and do not refit any coefficients. Above the cut both fields agree exactly. Existing I=0 equilibria and the stored training cycles and neutral fold trajectories remain unchanged when they remain above the cut; verify saved trajectories/minima rather than assuming this for all orbits.

This finite correction is not a proof of nonnegative calcium for arbitrary hidden state or input. `audit_lower_guard.py` checks the saved minima and a specified family of reset trajectories; root-finding and integrations have finite tolerances. The coefficient is a strong illustrative choice, not an optimum.

The speed experiment uses the same newly built PWA NEST model and binary for three- and four-zone variants, with one thread, identical node count, initial state, step, output, event recorder and run durations. Calcium upward-threshold spikes are recorded; no SIC is calculated. The model exposes the count of crossings of the added guard. It measures the implementation cost of one extra zone at the tested inputs and deterministic workloads, not any network speedup or universal timing guarantee. A separate reset condition uses an identical initial state taken from the original model after I=0.2 then I=1.2, and simulates at I=0: it exercises the guard, but one transient followed by relaxation does not measure performance at high sustained guard-crossing frequency.

Seven constant-IP3 values by default produce runtime and overhead curves; the separate reset appears in the CSV but not the constant-input curves. The test uses three timed repeats plus one warmup with alternating model order; setup and diagnostic recording are separate from timed `nest.Run`. Raw measurements, per-run guard-crossing and event counts, source candidate hashes and module hash are saved. Negative overhead is possible due to timing variation. Repeat counts do not provide a confidence interval without further assumptions.

The code is based on the preceding event-output benchmark and is prepared without access to NEST in the preparation environment. Compile and run the smoke test on the server; do not treat the server experiment as validated until its diagnostic and encoding checks pass.
