# Пробное преобразование Y=(C,logit(h),I)

Пользователь разрешил отдельную ветку blueprint с преобразованными координатами.
Здесь PWA строится в Y=(C,z,I), z=log(h/(1-h)), а не в физических (C,h,I).
Физическое поле после обратного преобразования, как правило, не PWA.
Предыдущие физические и плотные модели сохранены без изменений.

## Что сохраняется

- C и I остаются физическими, единицы мкМ и секунды прежние.
- Спектральные C-пороги не меняются: AM 3 порога/4 области, FM 7/8.
- Число свободных коэффициентов прежнее: 14 AM, 22 FM.
- Idot=-(I-I_b)/tau остаётся точным третьим уравнением.
- Скачок входа меняет только I. C,z сохраняются, значит сохраняется и h.
- Порог h=h_star при необходимости становится z=logit(h_star).
- Внутреннее состояние действительно хранится как Y; при интегрировании
  `latent.rhs` не вычисляет sigmoid. Обратное преобразование выполняется для
  физического вывода. Для C и кальций-зависимого SIC оно вообще не требуется.

## Точное исходное преобразованное поле

Сначала применяется правило цепочки к исходной Li–Rinzel:

Cdot=f_C(C,sigmoid(z),I),
zdot=f_h(C,h,I)/(h*(1-h)), h=sigmoid(z).

Для используемого LR:
zdot=.2*[Q(I)*(1+exp(-z))-C*(1+exp(z))],
Q(I)=1.049*(I+.13)/(I+.9434).

Затем аппроксимируется именно это полное поле. Простая подстановка имени z
вместо h в исходное уравнение не выполняется. `transformed_lr_field` проверен
по chain rule и complex-step Jacobian. В исходных равновесиях J_Y=T J_X T^-1,
T=diag(1,1/[h*(1-h)]), поэтому источник спектральной эвристики не меняется.
Это свойство точного преобразования, а не автоматическая гарантия точности PWA.

Преобразование определено только при 0<h<1. Начальные h=0 или h=1 отвергаются;
данные не обрезаются. При конечном z математически 0<sigmoid(z)<1. Для больших
|z| возможно насыщение округления до 0/1; число таких выходов сохраняется,
в этом эксперименте их нет. Положительность C из этого не следует.

## Класс аппроксимации

Для первых двух компонент:
F(Y)=b+a_C*C+a_z*z+a_I*I+sum_j u_j*max(0,C-theta_j).

Общие z/I-столбцы обеспечивают непрерывность на C-плоскостях. Региональный
спектр задаётся той же trace/determinant параметризацией, что в физическом
эксперименте; последовательность source node/focus/saddle типов сохраняется
жёстко. Это компактная PWA в Y, без добавочных I-порогов и без полиномов.

Аналитический региональный поток exp(t*[[A,b],[0,0]]) работает в Y.
После него h=sigmoid(z). Первый выход из региона нужно локализовать отдельно;
полный аналитический событийный решатель этим экспериментом не реализован.
Полные независимые траектории получены DOP853 непосредственно в Y.

## Контроль: не приписывать повторную подгонку преобразованию

Для прежней физической PWA построен контроль с прежней C(t) при h0=.8.
Берётся alpha=mean(h*(1-h)) на обучающих LR-данных, beta=.8-alpha*logit(.8).
В старых коэффициентах выполняется аффинная замена h_lin=alpha*z+beta,
после чего физический readout интерпретируется как sigmoid(z).

Это **не** точный нелинейный push-forward старой PWA. Это контроль,
сохраняющий кальциевую динамику и показывающий эффект одного bounded readout.
Для того же начального h=.8 совпадают Cdot0 и замкнутые коэффициенты Cddot,
значит C(t) совпадает и при спадах I, и при I-скачках. При других начальных h
такого тождества нет; это отдельно проверяется диагностическими протоколами.
Контроль сохранён в *_calcium_matched_control.json.

В каждой полосе при B!=0:
Cdot=a_j*C+B*z+cI*I+b_j,
zdot=d_j*C+D*z+dI*I+e_j.

Исключение z даёт:
Cddot=(a_j+D)*Cdot-(a_j*D-B*d_j)*C+(B*e_j-D*b_j)
      +(B*dI-D*cI)*I+cI*Idot.

Это то же семейство кальциевых уравнений, что в физической C-пороговой PWA.
Преобразование только h не расширяет класс возможных C(t), хотя меняет
физическую интерпретацию второго состояния и критерий подбора. Для более
свободной физической C-динамики потребуются другие координаты или геометрия.
Невозможность хорошей подгонки текущего класса этим не доказана.

## Подбор и проверка

Два старта: контроль с прежней кальциевой динамикой и nonlinear least-squares
по точному преобразованному LR-полю на обучающих траекториях. Затем два
ограниченных local least_squares запуска (max_nfev=150 каждый) и Powell
(maxfev=3000). Спектральные типы ограничены жёстко; пороги не оптимизируются.
Полные bounds, истории оценок и статусы optimizer сохранены в *_fit.json.

Train тот же, что в физической PWA: пять фиксированных I по 1600 с и спады
IP3 tau=20,100 с по 180 с. Начальные физические состояния совпадают у LR,
контроля и нового кандидата; преобразование выполняется после их задания.

Автономные residual scales: Cmin=.02 мкМ, Cmax=.05 мкМ,
period=1 с AM/3 с FM; отсутствующий целевой цикл получает штраф 15.
Отрицательный C:/.005, превышение C_max:/.02. Дополнительные мягкие residual
h_min,h_max с масштабом .1 используют event-sampled extrema native engine
для ускорения; независимая физическая проверка использует полные выходы.
Пороги равновесной ветви по I:/.03. Динамический RMSE-нормированный residual
масштабируется [.03 мкМ,.05] для C,h и sqrt(N). Regularization=.005.
Потери с физическим экспериментом напрямую не сравниваются: критерии разные.

Исторические диагностики: пять других фиксированных I, спады tau=2,50 с,
периодические и нерегулярные скачки с остановкой стимуляции. Эти протоколы
были известны до эксперимента. Новые, не используемые при подборе: h0=.65,.9,
C0=.08, tau=35 с, duration=180 с, остальные уровни IP3 те же по модели.
Итого 18 протоколов для каждой модели. Ни один holdout не выбирает параметры.

Ускоритель подбора: существующий exact-flow native engine для постоянного I
и RK4 для C,z с точным I на стадиях (maxdt=.025, уменьшается при больших
спектральных масштабах). Независимая проверка: DOP853 в Y,
rtol=2e-9,atol=2e-11,max_step=.15; для динамических train дополнительно
RK4 maxdt=.005. Все сравнения выполняются на одной выходной временной сетке:
.2 с при фиксированном I, .1 с на динамических входах. Периодическая метрика
не уточняет пики между выходными отсчётами.

C,h нарушения, число пиков, raw waveform RMSE, новые начальные условия и
неудачные результаты сохраняются. Нет заявления о глобальном оптимуме,
полной бифуркационной достоверности, готовности SIC/NEST или ускорении.

## Воспроизведение

Из /workspace/PWL-NEST:

```bash
bash scripts/setup.sh
.venv/bin/python -m unittest discover -s tests -v
OPENBLAS_NUM_THREADS=1 .venv/bin/python scripts/check_logit.py
# Повторить подбор; перезапишет только logit-результаты:
OPENBLAS_NUM_THREADS=1 .venv/bin/python scripts/fit_logit.py
.venv/bin/python scripts/summarize_logit.py
# Либо повторить только независимые траектории:
OPENBLAS_NUM_THREADS=1 .venv/bin/python scripts/validate_logit.py
```

```python
from pwl_nest.logit_pwa import LogitPWA, simulate_logit
model=LogitPWA.load('models/logit_pwa/AM.json')

latent=info['latent']  # интегрировалось именно это состояние
```
