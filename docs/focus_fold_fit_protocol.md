# Протокол трёхзонного подбора с закреплённой складкой и фокусами

Статус: утверждённая постановка серверного подбора; выполнен локальный smoke для AM, полный многозапуск ещё предстоит. Приоритет имеет этот раздел там, где исторические заметки ниже описывают прежние пробные настройки.

**Окончательный выбор пользователя:** физичность — жёсткое условие допуска, а не слагаемое потерь. Целевая функция состоит только из ошибок Cmin, Cmax, периода и формы цикла; никакой регуляризации и штрафа за отрицательный C в ней нет. Нефизичные кандидаты и ненайденные/непроверенные циклы не сохраняются как допустимые; большое значение residual для внутренней работы численного алгоритма — лишь маркер неудачной пробы, а не её научная ошибка. Старые exploratory результаты с отрицательным C — только диагностика, не часть этого протокола.

Под фазовой ошибкой понимается форма цикла: максимумы совмещаются, время нормируется на период, затем амплитуда нормируется к [0,1] и сравниваются 64 отсчёта. Для каждого I: `((Cmin−CminLR)/0.03)^2 + ((Cmax−CmaxLR)/0.08)^2 + ((T−TLR)/5)^2 + mean((shape−shapeLR)^2)/0.1^2`; единицы C — мкМ, времени — с. Масштаб формы .1 — выбранный технический вес, настраивается одинаково для всех режимов через `--shape-scale`. Это сравнение формы после совмещения пиков, не абсолютной фазы ответа на динамический вход. Эталонный массив `target_shape` хранится в исходных данных.

Сервер: `run_focus_fit_batch.py --output results/focus_fold_main --seeds 16 --workers 16 --max-nfev 80`. Для AM есть один совместимый seed, стартовые векторы локально рандомизируются; AFM/FM запускают отдельный численный поиск начального seed для каждого повтора и могут остаться без пригодного старта. Это честный статус незавершённого поиска, а не доказательство невозможности. Перед основным запуском необходим smoke. Каждый процесс пишет собственный log и status.json; последующие рестарты пропускают существующие каталоги, то есть не возобновляют прерванную оптимизацию. Для повтора используйте новый каталог. Использование отдельных логов и выключение внутренних потоков BLAS позволяют запускать до указанного числа одновременных процессов.


## Поле и фиксируемые величины

Используем ту же непрерывную систему `Cdot=a(q-N(C,I))`, `qdot=b(H(C,I)-q)` и два фиксированных порога C. Для каждой из AM, AFM, FM исходные `paper/data/physical_models/fixed_fold/<case>/parameters.json`, включая LR-данные, координаты покоя и порогов, закреплены по SHA256 в fold_audit. Важно: I=0 фиксирует заданное равновесие (C0,q0), а не отдельный параметр I. Фиксируются входы I1,I2, при которых равновесие пересекает соответствующие границы. Через линейную систему исключаются четыре коэффициента. a,b и пороги на первом этапе сохраняются как в исходной модели. Возможная позднейшая оптимизация a,b — отдельное изменение протокола.

На трёх региональных матрицах задаются `T_L<0, T_M>0, T_R<0` и `T_j^2-4D_j<0`; практическая реализация требует отдельно указать масштабы и запас от вырождения. Это три фокуса: устойчивый, неустойчивый, устойчивый. В `check_focus_feasibility.py` запас задан для T и 4D−T² числом 0.01 в соответствующих единицах; это предварительная техническая настройка, а не фундаментальный универсальный критерий и не основание для сравнения качества.

## Складка и уменьшение размерности

Положение I*=I_fold фиксируется на входе. При заданных независимых коэффициентах и выбранном зависимом pivot одновременно решаются уравнения согласования сегментов и сумма T_j tau_j=0. Количество неизвестных (времена пролёта плюс pivot) совпадает с количеством условий замыкания и нейтральности. При успехе снимается одна независимая степень свободы *локально*, если соответствующий якобиан невырожден. Могут существовать несколько корней; непрерывность выбора проверяется продолжением и проверкой маршрута. Решение до конечного допуска, а не точное гарантированное совпадение. Дополнительно нужны трансверсальность, первый выход, положительные времена, G_qq != 0 и G_I != 0 для невырожденной складки; выборка не является строгой сертификацией. Всякий алгоритм должен сохранять статус и невязки.

Фокусные ограничения проверяются для решённой модели. При получении нового набора независимых параметров в рамках схемы с исключённым pivot внутреннюю задачу обычно нужно решать заново. Начальное приближение можно брать из близкого уже найденного решения, но после этого требуется проверять невязку. Дополнительные попытки, другой pivot и продолжение помогают, но численный сбой не означает доказанного отсутствия допустимого поля. Оптимизация одновременно по всем параметрам с ограничениями является альтернативой и не исключает pivot явно.

## Циклы и потери — постановка

Теорема 5(b), уже сопоставленная с системой в `paper/return_map_notes.md`, даёт существование/единственность устойчивого цикла при наличии всех её гипотез и равновесия в средней зоне. Она не утверждает, что цикл имеет заранее выбранный маршрут, положителен по C, его численный поиск сошёлся или что нужные условия работают на концах интервала. Вне его нужны отдельные проверки.

Для каждого из семи обучающих I решить соответствующее уравнение возврата; разрешить как минимум маршруты L–M–R и M–R и различать случаи без пересечения границы. При касании аккуратно переключать маршрут, а не продолжать гладкую формулу через вырождение. Выбрать физически допустимый устойчивый цикл с `M<1`, проверить направления, первый выход и диапазон C; не путать нестабильный и устойчивый корни. Минимум и максимум найти на аффинных участках и проверить сходимость; период — сумма времен. Использовать утверждённую функцию Cmin/0.03, Cmax/0.08, T/5 и нормированной формы цикла/0.1; регуляризация отсутствует. Четыре holdout точки по каждому режиму не участвуют в подборе. Обработать отдельно нерешённую численную задачу, нефизичную орбиту и отсутствие допустимого корня; не считать неуспех алгоритма доказательством отсутствия орбиты.

## Уже выполненные проверки

`OPENBLAS_NUM_THREADS=1 PYTHONPATH=src:scripts python scripts/check_focus_feasibility.py --bounds 40 --starts 8 --margin .01 --output results/focus_screen/margin_001.json` нашёл статические решения со всеми тремя фокусами для AM, AFM и FM. Это только фиксированные равновесия + спектры; складка и циклы не проверены. При bounds=4 из 8 стартов решения найдены для AM, но не для AFM и FM. Это не доказательство несовместимости. Проверка статического исключения сравнена с прежним `anchor_model` тестом `tests/test_focus_screen.py`.

`probe_focus_fold.py` попробовал четыре pivot для одного статического старта каждого режима: предыдущий решатель складки ни разу не сошёлся. `find_focus_fold_seed.py` сделал одну ограниченную совместную попытку для каждого режима; все остались unresolved, причём некоторые времена упёрлись в верхние границы. Это не является полноценным многозапусковым поиском и не подтверждает отсутствие решения. Не подменять этим полный подбор.

Следующее: получить хотя бы один допустимый старт fold+foci с проверенным маршрутом в каждом режиме, затем реализовать и протестировать два маршрута для вычисления потери, проверить повторяемость конечных разностей при повторных одинаковых x и провести одинаковый multistart/protocol для AM/AFM/FM. До этого результаты моделей не считать подобранными. Оптимизацию не запускать параллельно с чувствительным benchmark времени NEST.


## Дополнения к эксперименту

- Совместный предварительный поиск дал подходящие после перерешивания pivot-уравнений старты со всеми фокусами и нейтральной орбитой для AM и AFM: `results/focus_screen/am_fold_foci_seed` и `afm_fold_foci_seed`. AM: logM около −3.3e−14, максимальная невязка около 2.1e−11, дискр. [−0.0100, −0.3716, −0.4176]. AFM: logM около 8.4e−14, все дискр. отрицательны. Маршрут и позитивность этих орбит проверены по конечной сетке, невырожденность численно; это не полноценный подбор и не доказательство глобальной полноты.
- `return_cycle_metrics.py` реализует три маршрута (оба порога, только верхний, только нижний). По двум тренировочным входам каждого старого кандидата начальная оценка из прямого интегрирования дала 6/6 совпадающих с IVP устойчивых циклов. Без хороших начальных времён те же маршруты не разрешались. Поиск конечный; тест `tests/test_return_cycle_metrics.py` проверяет один случай.
- У нового AM-старта найдены семь положительных тренировочных циклов. Краткий smoke из 3 оценок оптимизатора `am_return_fit_smoke` немного снизил тренировочную функцию 18.0786 → 18.0697 и остановился по бюджету; holdout не вычислен и глобальная оптимальность не утверждается. Ошибка и прежняя функция сопоставимы только в пределах принятой нормировки и оценивания метрик.
- У AFM-старта найдены математические циклы, но во всех семи тренировочных точках Cmin отрицателен. Для предварительного поиска разрешены такие промежуточные кандидаты со штрафом `max(0,0.001−Cmin)/0.02`; они никогда не должны считаться физически допустимым финальным результатом. Краткий smoke `afm_return_fit_smoke` не сошёлся и физичность не восстановил. Точная эксплоративная функция дополнена штрафом относительно AM и не сравнивается по абсолютному значению с AM.
- У FM пока не найден одновременно складочный и трёхфокусный старт; без него `fit_focus_fold_return.py` не запускает подбор. Попытки не доказывают невозможность.
