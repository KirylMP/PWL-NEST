# Каталог астроцитарных моделей

Это общая точка входа для текущих AM/FM моделей с преобразованием координаты. Запускайте команды из корня репозитория в окружении с зависимостями проекта и NEST 3.10.

```text
astrocyte_lab/
  models/                     каждая сохранённая модель в своей папке
    am_2thr_<прогон>/
      parameters.json         параметры для подбора и NEST
      bifurcation.png         график, если построен при проверке
      branches.json           данные конечного скана, если он завершён
      metadata.json           происхождение, состояние подбора, оптимизаторы
  scripts/                    команды импорта, подбора и запуска NEST
  runs/                       отдельная папка каждого прогона и его логи
```

Каталог `models/` хранит копии параметров, а `runs/` — подробные результаты экспериментов. Папки автоматически не добавляются в Git: это результаты конкретной машины; при необходимости их можно добавить явно через `git add -f` или переслать архивом. Старые эксперименты остаются источником вычислительного кода и не перемещаются: они также содержат зависимости и исходные данные.

## Перенос готового прогона

```bash
python3 astrocyte_lab/scripts/import_run.py ПУТЬ_К_ПАПКЕ_ПРОГОНА
python3 astrocyte_lab/scripts/list_models.py
```

Поддерживаются папки `base_nest_...` с `fit/am` и `fit/fm` и папки `rest_...` с `am` и `fm`. Файлы копируются и не изменяются. Повторный импорт той же модели безопасен; совпадение имени с другими параметрами вызывает ошибку. По умолчанию импортируется кандидат стадии `closed`; `--allow-incomplete` разрешает импортировать предыдущую стадию. `complete` в метаданных означает только стадию `closed`, а не достижение сходимости или качество модели. Если график не построился, поле `has_bifurcation` будет false. Исходный путь и SHA-256 записываются в `metadata.json`.

## Новый подбор

```bash
bash astrocyte_lab/scripts/fit.sh base       # AM: 2 порога; FM: 3
bash astrocyte_lab/scripts/fit.sh refined    # AM: 4 порога; FM: 7
bash astrocyte_lab/scripts/fit.sh focus      # FM: 3 порога, нижняя область — устойчивый фокус
bash astrocyte_lab/scripts/fit.sh split      # FM: 4 порога, дополнительная нижняя неустойчивая область
bash astrocyte_lab/scripts/fit.sh split_fixed # FM: 4 порога, закреплены обе границы седла LR
bash astrocyte_lab/scripts/fit.sh six_fixed   # FM: 6 областей, 5 переходов LR
bash astrocyte_lab/scripts/fit.sh full_fixed  # FM: 8 областей, 7 переходов LR
```

В процессе печатается `RUN_DIR`; внутри лежат `am`, `fm`, `logs`. После завершения модели копируются в `models/`. Если один из этапов завершился с ошибкой, журнал и промежуточные файлы сохраняются; стадии `closed`, которые успели получиться, всё равно импортируются. Все старые настройки окружения подбора сохраняются: например, `MODELS=fm`, `GEOMETRY_MAXFEV`, `CLOSED_MAXFEV`, `POINCARE_WEIGHT_SCALE`, `WORKERS`. Полные условия, ограничения и веса описаны в `experiments/fm_am_minimal_zones/rest_refinement/README.md`.

Режим `focus` использует три фиксированных порога и жёсткие типы: устойчивый фокус, седло, неустойчивый фокус, устойчивый фокус. Покой при I=0 и два перехода равновесия фиксированы; на стадии closed требуется подтверждённая верхняя складка цикла. Начальный кандидат можно выбрать через `FM_PARENT_CANDIDATE=/полный/путь/candidate.json` — только трёхпороговая модель с тем же преобразованием и исходными порогами. Если складку не удаётся инициализировать, предшествующая модель импортируется как незавершённая (`stage` не `closed`).

Для `focus` дополнительно запускается сеточный поиск циклов LR и PWA возле нижнего перехода (по умолчанию I=0.525–0.534). `lower_bifurcation.png` и `lower_bifurcation.json` кладутся в папку модели; диагностика поиска и отсечённые интегрирования сохраняются в JSON. Сетка и число начальных точек не доказывают отсутствие ветви и этот поиск не является продолжением. Настройки: `LOWER_POINTS` (81), `LOWER_SEEDS` (48), `LOWER_WORKERS` (4), `LOWER_I_START`, `LOWER_I_STOP`.

Режим `split` добавляет физический порог C=0.05214116272147648 мкМ к трём прежним FM-порогам; это C равновесия LR на нижнем спектральном переходе. Порядок областей: устойчивый фокус, неустойчивый фокус, седло, неустойчивый фокус, устойчивый фокус. Переход первого порога фиксируется при I=0.5290700389163683; пересечение последнего — при I=0.8600205557570602. Остальные положения порогов прежние, пересечение старого первого порога по I не закреплено. Покой при I=0 и верхняя складка цикла сохраняются как в `focus`. Начальные параметры берутся из трёхпорогового FM (`FM_PARENT_CANDIDATE`), затем подбираются заново. Выполняется такой же сгущённый анализ нижнего перехода; полученная последовательность типов сама по себе не гарантирует существование неустойчивого цикла.

Режим `split_fixed` задаёт C и I обеих седло-узловых точек LR: (0.06128930910964862, 0.5439919432478553) и (0.1357042423799119, 0.48230398233782223), единицы мкМ. Остальные закреплённые условия: покой LR при I=0, нижний переход при C=0.05214116272147648, I=0.5290700389163683, и верхний переход при C=0.3623042888621253, I=0.8600205557570602. Три региональных определителя вычисляются из этих условий; неподходящие типы и нефизические высоты отклоняются. У PWA точки на границах являются негладкими событиями равновесий: совпадение C и I не делает их гладкими седло-узловыми бифуркациями LR и не фиксирует h. Складка большого цикла дополнительно ищется численно. Ограничения могут оказаться несовместимыми с параметризацией или помешать инициализации; тогда сохраняются доступные промежуточные результаты и логи.

Режим `six_fixed` объединяет первые три узла восьмиобластного кандидата: устойчивый узел, устойчивый фокус, седло, неустойчивый узел, неустойчивый фокус, устойчивый фокус. Стартовые параметры берутся из архивного `previous_selected.json` (восьмиобластный candidate 5), затем подбираются заново. Пять порогов и соответствующих пересечений фиксированы по LR: (C, I) = (0.0486193511, 0.5107261652), (0.0612893091, 0.5439919432), (0.1357042424, 0.4823039823), (0.2518184158, 0.5747315356), (0.3926251934, 0.8600205558), в мкМ. Первый и четвёртый — переходы узел–фокус, второй и третий — седло-узловые точки, последний — верхний переход устойчивости. Строится сгущённый анализ нижнего перехода; поскольку здесь нет отдельной неустойчивой области между устойчивым фокусом и седлом, нижний Hopf LR при I≈0.529 не зафиксирован и его воспроизведение не гарантируется. Прежние условия покоя и верхней складки большого цикла сохраняются.

Режим `full_fixed` использует все восемь региональных типов равновесий LR: устойчивый узел, устойчивый фокус, неустойчивый фокус, неустойчивый узел, седло, неустойчивый узел, неустойчивый фокус, устойчивый фокус. Семь физических C-порогов совпадают с LR при соответствующих изменениях типа: 0.0486193511, 0.0521411627, 0.0548446931, 0.0612893091, 0.1357042424, 0.2518184158, 0.3926251934; значения I закреплены соответственно 0.5107261652, 0.5290700389, 0.5373937039, 0.5439919432, 0.4823039823, 0.5747315356, 0.8600205558. Условия на покой и верхнюю складку большого цикла сохраняются. Исходные коэффициенты берутся из предыдущего восьмиобластного candidate 5; недостающие по типу области инициализируются из родственных областей и затем подбираются. Переходы PWA происходят на границах областей; совпадение порогов и I не означает точного совпадения h, гладких бифуркационных механизмов или ветвей циклов LR. Ограничения могут оказаться несовместимы или помешать поиску верхней складки. Расчёт выполняет конечный скан, включая нижнюю область; отсутствие найденного цикла не доказывает его отсутствия.

## Запуск NEST

Выберите пути из `list_models.py` и передайте оба явно:

```bash
bash astrocyte_lab/scripts/nest.sh \
  astrocyte_lab/models/ИМЯ_AM \
  astrocyte_lab/models/ИМЯ_FM
```

Скрипт собирает NEST-модуль из выбранных файлов и проводит проверку интегрирования, замеры для одиночных астроцитов и сеть из 10 возбуждающих нейронов с 90 астроцитами. Путь к результатам выводится как `RUN_DIR`, внутри папки `benchmark` и `network`. Сейчас NEST принимает только модели AM с двумя и FM с тремя порогами, стадии `closed`; расширенные конструкции ещё требуют расширения NEST-генератора. Результаты зависят от сценария и не гарантируют близости к LR в других условиях. Можно задать `NEST_THREADS`, `NETWORK_THREADS`, `NEST_DURATION_S`, `NETWORK_DURATION_S` и остальные параметры исходных NEST-скриптов.
