# Каталог астроцитарных моделей

Это общая точка входа для текущих AM/FM моделей с преобразованием координаты. Запускайте команды из корня репозитория в окружении с зависимостями проекта и NEST 3.10.

```text
astrocyte_lab/
  models/                     каждая сохранённая модель в своей папке
    am_2thr_<прогон>/
      parameters.json         параметры для подбора и NEST
      bifurcation.png         график, если построен при проверке
      branches.json           данные конечного скана, если он завершён
      metadata.json           происхождение, состояние подбора, оптимизаторы
  scripts/                    команды импорта, подбора и запуска NEST
  runs/                       отдельная папка каждого прогона и его логи
```

Каталог `models/` хранит копии параметров, а `runs/` — подробные результаты экспериментов. Папки автоматически не добавляются в Git: это результаты конкретной машины; при необходимости их можно добавить явно через `git add -f` или переслать архивом. Старые эксперименты остаются источником вычислительного кода и не перемещаются: они также содержат зависимости и исходные данные.

## Перенос готового прогона

```bash
python3 astrocyte_lab/scripts/import_run.py ПУТЬ_К_ПАПКЕ_ПРОГОНА
python3 astrocyte_lab/scripts/list_models.py
```

Поддерживаются папки `base_nest_...` с `fit/am` и `fit/fm` и папки `rest_...` с `am` и `fm`. Файлы копируются и не изменяются. Повторный импорт той же модели безопасен; совпадение имени с другими параметрами вызывает ошибку. По умолчанию импортируется кандидат стадии `closed`; `--allow-incomplete` разрешает импортировать предыдущую стадию. `complete` в метаданных означает только стадию `closed`, а не достижение сходимости или качество модели. Если график не построился, поле `has_bifurcation` будет false. Исходный путь и SHA-256 записываются в `metadata.json`.

## Новый подбор

```bash
bash astrocyte_lab/scripts/fit.sh base       # AM: 2 порога; FM: 3
bash astrocyte_lab/scripts/fit.sh refined    # AM: 4 порога; FM: 7
bash astrocyte_lab/scripts/fit.sh focus      # FM: 3 порога, нижняя область — устойчивый фокус
bash astrocyte_lab/scripts/fit.sh split      # FM: 4 порога, дополнительная нижняя неустойчивая область
bash astrocyte_lab/scripts/fit.sh split_fixed # FM: 4 порога, закреплены обе границы седла LR
bash astrocyte_lab/scripts/fit.sh six_fixed   # FM: 6 областей, 5 переходов LR
bash astrocyte_lab/scripts/fit.sh full_fixed  # FM: 8 областей, 7 переходов LR
bash astrocyte_lab/scripts/fit_full_h.sh      # то же с точными h во всех переходах
```

В процессе печатается `RUN_DIR`; внутри лежат `am`, `fm`, `logs`. После завершения модели копируются в `models/`. Если один из этапов завершился с ошибкой, журнал и промежуточные файлы сохраняются; стадии `closed`, которые успели получиться, всё равно импортируются. Все старые настройки окружения подбора сохраняются: например, `MODELS=fm`, `GEOMETRY_MAXFEV`, `CLOSED_MAXFEV`, `POINCARE_WEIGHT_SCALE`, `WORKERS`. Полные условия, ограничения и веса описаны в `experiments/fm_am_minimal_zones/rest_refinement/README.md`.

Режим `focus` использует три фиксированных порога и жёсткие типы: устойчивый фокус, седло, неустойчивый фокус, устойчивый фокус. Покой при I=0 и два перехода равновесия фиксированы; на стадии closed требуется подтверждённая верхняя складка цикла. Начальный кандидат можно выбрать через `FM_PARENT_CANDIDATE=/полный/путь/candidate.json` — только трёхпороговая модель с тем же преобразованием и исходными порогами. Если складку не удаётся инициализировать, предшествующая модель импортируется как незавершённая (`stage` не `closed`).

Для `focus` дополнительно запускается сеточный поиск циклов LR и PWA возле нижнего перехода (по умолчанию I=0.525–0.534). `lower_bifurcation.png` и `lower_bifurcation.json` кладутся в папку модели; диагностика поиска и отсечённые интегрирования сохраняются в JSON. Сетка и число начальных точек не доказывают отсутствие ветви и этот поиск не является продолжением. Настройки: `LOWER_POINTS` (81), `LOWER_SEEDS` (48), `LOWER_WORKERS` (4), `LOWER_I_START`, `LOWER_I_STOP`.

Режим `split` добавляет физический порог C=0.05214116272147648 мкМ к трём прежним FM-порогам; это C равновесия LR на нижнем спектральном переходе. Порядок областей: устойчивый фокус, неустойчивый фокус, седло, неустойчивый фокус, устойчивый фокус. Переход первого порога фиксируется при I=0.5290700389163683; пересечение последнего — при I=0.8600205557570602. Остальные положения порогов прежние, пересечение старого первого порога по I не закреплено. Покой при I=0 и верхняя складка цикла сохраняются как в `focus`. Начальные параметры берутся из трёхпорогового FM (`FM_PARENT_CANDIDATE`), затем подбираются заново. Выполняется такой же сгущённый анализ нижнего перехода; полученная последовательность типов сама по себе не гарантирует существование неустойчивого цикла.

Режим `split_fixed` задаёт C и I обеих седло-узловых точек LR: (0.06128930910964862, 0.5439919432478553) и (0.1357042423799119, 0.48230398233782223), единицы мкМ. Остальные закреплённые условия: покой LR при I=0, нижний переход при C=0.05214116272147648, I=0.5290700389163683, и верхний переход при C=0.3623042888621253, I=0.8600205557570602. Три региональных определителя вычисляются из этих условий; неподходящие типы и нефизические высоты отклоняются. У PWA точки на границах являются негладкими событиями равновесий: совпадение C и I не делает их гладкими седло-узловыми бифуркациями LR и не фиксирует h. Складка большого цикла дополнительно ищется численно. Ограничения могут оказаться несовместимыми с параметризацией или помешать инициализации; тогда сохраняются доступные промежуточные результаты и логи.

Режим `six_fixed` объединяет первые три узла восьмиобластного кандидата: устойчивый узел, устойчивый фокус, седло, неустойчивый узел, неустойчивый фокус, устойчивый фокус. Стартовые параметры берутся из архивного `previous_selected.json` (восьмиобластный candidate 5), затем подбираются заново. Пять порогов и соответствующих пересечений фиксированы по LR: (C, I) = (0.0486193511, 0.5107261652), (0.0612893091, 0.5439919432), (0.1357042424, 0.4823039823), (0.2518184158, 0.5747315356), (0.3926251934, 0.8600205558), в мкМ. Первый и четвёртый — переходы узел–фокус, второй и третий — седло-узловые точки, последний — верхний переход устойчивости. Строится сгущённый анализ нижнего перехода; поскольку здесь нет отдельной неустойчивой области между устойчивым фокусом и седлом, нижний Hopf LR при I≈0.529 не зафиксирован и его воспроизведение не гарантируется. Прежние условия покоя и верхней складки большого цикла сохраняются.

Режим `full_fixed` использует все восемь региональных типов равновесий LR: устойчивый узел, устойчивый фокус, неустойчивый фокус, неустойчивый узел, седло, неустойчивый узел, неустойчивый фокус, устойчивый фокус. Семь физических C-порогов совпадают с LR при соответствующих изменениях типа: 0.0486193511, 0.0521411627, 0.0548446931, 0.0612893091, 0.1357042424, 0.2518184158, 0.3926251934; значения I закреплены соответственно 0.5107261652, 0.5290700389, 0.5373937039, 0.5439919432, 0.4823039823, 0.5747315356, 0.8600205558. Условия на покой и верхнюю складку большого цикла сохраняются. Исходные коэффициенты берутся из предыдущего восьмиобластного candidate 5; недостающие по типу области инициализируются из родственных областей и затем подбираются. Переходы PWA происходят на границах областей; совпадение порогов и I не означает точного совпадения h, гладких бифуркационных механизмов или ветвей циклов LR. Ограничения могут оказаться несовместимы или помешать поиску верхней складки. Расчёт выполняет конечный скан, включая нижнюю область; отсутствие найденного цикла не доказывает его отсутствия.

`full_h_fixed` добавляет к указанным семи C,I точное h равновесия LR в каждой точке и сохраняет LR покой при I=0. Наклоны обеих PWA нульклин между последовательными точками вычисляются аналитически, из них вычисляются следы и определители регионов; неподходящие типы и границы отклоняются. Это существенно сокращает свободу параметров. Предварительная инициализация сначала максимизирует минимальный запас ограничений, а затем приближается к сохранённой модели full_fixed, удерживая положительный запас; `FULL_H_INIT_STARTS` (12) и `FULL_H_INIT_MAXITER` (1500) задают бюджет. Численная неудача не доказывает математическую невозможность. Складка большого цикла дополнительно ищется и проверяется как раньше. Переходы PWA негладкие даже при совпадении всей тройки. Проверочные поля `fixed_event_target_h`, `fixed_event_heights` и `fixed_event_height_residuals` находятся в parameters.json. Обёртка `fit_full_h.sh` выбирает последнюю закрытую full_fixed модель; конкретный parameters.json можно передать аргументом.

### Локальный показатель двух нижних фокусов FM

`bash astrocyte_lab/scripts/fit_local_focus.sh [parameters.json]` запускает независимые продолжения одного закрытого `full_fixed` кандидата. По умолчанию выбирается последняя модель с зафиксированной складкой, исключая результаты этого же эксперимента. Для областей 2 и 3 вычисляется `log M0 = π Σ T/sqrt(4D−T²)`; к лоссу закрытой стадии прибавляется `FM_LOCAL_FOCUS_WEIGHT * (max(0, log M0 − target)² + max(0, floor − log M0)²)`. Значения по умолчанию: `FM_LOCAL_FOCUS_TARGETS='2 5 8'`, `FM_LOCAL_FOCUS_FLOOR=0.1`, `FM_LOCAL_FOCUS_WEIGHT=100`. Это мягкий штраф, а не гарантированное ограничение; показатели и компоненты записываются в `parameters.json`. Можно менять вес, цели и бюджет `CLOSED_MAXFEV`, а также остальные настройки closed стадии. Каждый вариант стартует из одной и той же модели, проверяет её сохранённую складку и сохраняется отдельно в `runs/` и `models/`, вместе с графиками и логами. Условия на покой, семь событий и верхнюю складку сохраняются. `WORKERS` и `LOWER_WORKERS` ускоряют только сканирование, сам Powell не распараллелен.

Показатель относится к локальному отображению на границе при критическом значении параметра; он не является измеренным мультипликатором конечного цикла и сам не фиксирует начало большой орбиты. Параметр target выбран для сравнения, а не как значение, полученное для LR. Начало большой орбиты следует оценивать отдельным поиском и проверкой замыкания; конечная сетка и возможные тайм-ауты не доказывают отсутствия цикла.

### Нижнее начало FM и проверка малых циклов

`python3 astrocyte_lab/scripts/check_fm_small_cycles.py MODEL_DIR --workers 16` повторно сканирует узкий интервал, по умолчанию 0.5228–0.5236, и для каждого обнаруженного цикла независимо интегрирует PWA из точки сечения в течение его периода. Результаты `small_cycle_check.json` и `small_cycle_check.png` записываются в папку модели. Замыкание проверяется в физической паре (C,h), порог `--closure-tol` по умолчанию 1e-5. Устойчивость берётся из исходного отображения, а не из независимого интегратора. Отсутствие найденного цикла не является доказательством отсутствия.

`bash astrocyte_lab/scripts/fit_lower_onset.sh MODEL_DIR/parameters.json` продолжает закрытый full_fixed FM кандидат с сохранением остальных ограничений и без штрафа на локальный показатель фокусов. На точках `FM_LOWER_LARGE_I` (по умолчанию `0.524,0.526,0.5275,0.528`) сначала считается конечный скан LR, затем при каждой оценке считается скан PWA. Штраф `FM_LOWER_LARGE_WEIGHT` (600) умножает средний квадрат числа лишних устойчивых циклов с физическим `Cmax >= FM_LOWER_LARGE_CMAX` (0.5 мкМ). Это дополнительный штраф к прежнему лоссу, не гарантия сдвига начала; он не штрафует недостающие и малые циклы. `FM_LOWER_LARGE_SEEDS` (32) задаёт число начальных точек. В `parameters.json` сохраняются `lower_large_cycle_report`, диагностика LR/PWA, настройки и компоненты лосса. Счётчик дискретный, сканы могут пропускать циклы или давать тайм-ауты, а Powell может не сдвинуться из-за плоского лосса; нужны независимая проверка и сравнение графиков. Дополнительные сканы увеличивают время каждой оценки. Исходные LR результаты выводятся в журнал и не являются доказательством отсутствия цикла.

## Подбор дополнительных верхних порогов

`bash astrocyte_lab/scripts/fit_upper.sh` последовательно подбирает четыре варианта из последнего завершённого `full_fixed` с проверенной складкой в каталоге моделей. Можно указать конкретный `parameters.json` первым аргументом. Старые семь порогов и семь I событий фиксируются, новые положения C являются параметрами оптимизации. Варианты: один порог с началом 0.70, один с началом 1.00 (оба имеют область [0.45, 1.35] мкМ), два с началами 0.70 и 1.00 (области [0.45, 0.895] и [0.905, 1.35]); три с началами 0.70, 0.95, 1.10 (области [0.45, 0.895], [0.905, 1.045], [1.055, 1.35]). На каждой новой области жёстко задан устойчивый фокус. Все варианты сохраняются отдельно; если один завершается ошибкой, последующие всё равно запускаются. Пороговые интервалы и число стартов ограничивают поиск, поэтому совпадение найденных результатов не доказывает глобального минимума. Новые конфигурации требуют отдельного расширения NEST-генератора; этот скрипт не запускает NEST.

## Запуск NEST

Для сравнения равновесий LR и сохранённой FM-модели:

```bash
python3 astrocyte_lab/scripts/plot_fm_equilibria.py astrocyte_lab/models/ИМЯ_FM
```

В папке модели создаются `equilibria_comparison.png` и `equilibria_comparison.json`. На рисунке отдельно показана увеличенная область седла с координатами C и h; существующие сканы циклов наложены как точки. Ветви равновесий вычисляются по сетке C; циклы из ранее сохранённых сканов, а не новые результаты продолжения.

`python3 astrocyte_lab/scripts/plot_fm_phase.py astrocyte_lab/models/ИМЯ_FM` строит `phase_near_onset.png` и JSON по точкам ближайшего сохранённого скана `lower_bifurcation.json`: нульклины, равновесия, сепаратрисы седла и найденные циклы LR/PWA. Циклы независимо интегрируются для проверки замыкания; полупрозрачные кривые не прошли эту проверку. Сепаратрисы начаты с конечным возмущением и конечным временем, расстояния являются оценкой по выборке, не доказательством бифуркации. Точки входа можно задать как `--inputs 0.525 0.5288 0.5292`.

`python3 astrocyte_lab/scripts/analyze_fm_onset.py astrocyte_lab/models/ИМЯ_FM --workers 16` ищет левую границу обнаружения большого устойчивого цикла LR и PWA и записывает `onset_boundary.json` и `onset_boundary.png`. По умолчанию I=0.48–0.532, 105 значений, 64 начальные точки на сечение и 12 шагов условного бисекции. Параметры изменяются через `--start`, `--stop`, `--points`, `--seeds`, `--bisections`, `--large-min`. Для нескольких найденных больших орбит сохраняются период, логарифм множителя, независимая DOP853 проверка замыкания и выборочное расстояние до седла. Сетка и бисекция уточняют границу обнаружения данного поискового метода; не обнаружить цикл не означает доказать его отсутствие, а результаты не классифицируют бифуркацию автоматически. В подбор никаких новых жёстких ограничений не добавляется.

`python3 astrocyte_lab/scripts/analyze_fm_separatrix.py astrocyte_lab/models/ИМЯ_FM --workers 16` численно исследует гипотезу петли седла: для LR и PWA сравнивает h первых пересечений устойчивой и неустойчивой сепаратрис с сечением C=0.2. Сохраняются `separatrix_onset.json` и `separatrix_onset.png`; при смене знака производится поиск кандидата и сверка невязки при уменьшенном начальном возмущении. Выбирается выходящая ветвь, которая сначала идёт влево по C; `--unstable-branch right` выбирает другую ветвь. Поиск использует конечные смещения, время интегрирования (по умолчанию 600 с), одну выбранную секцию и конечную сетку I: несовпадение, совпадение или отсутствие пересечения не являются полным доказательством механизма. При неоднозначных ветвях скрипт сообщает об этом; для каждого направления сохраняются конечная точка, время и причина остановки. Настройки: `--section`, `--epsilon`, `--max-time`, `--start`, `--stop`, `--points`, `--workers`, `--output-prefix`.

Выберите пути из `list_models.py` и передайте оба явно:

```bash
bash astrocyte_lab/scripts/nest.sh \
  astrocyte_lab/models/ИМЯ_AM \
  astrocyte_lab/models/ИМЯ_FM
```

Скрипт собирает NEST-модуль из выбранных файлов и проводит проверку интегрирования, замеры для одиночных астроцитов и сеть из 10 возбуждающих нейронов с 90 астроцитами. Путь к результатам выводится как `RUN_DIR`, внутри папки `benchmark` и `network`. Сейчас NEST принимает только модели AM с двумя и FM с тремя порогами, стадии `closed`; расширенные конструкции ещё требуют расширения NEST-генератора. Результаты зависят от сценария и не гарантируют близости к LR в других условиях. Можно задать `NEST_THREADS`, `NETWORK_THREADS`, `NEST_DURATION_S`, `NETWORK_DURATION_S` и остальные параметры исходных NEST-скриптов.
