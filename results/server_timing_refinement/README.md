# FM: штраф за абсолютные времена пиков

Исходный серверный кандидат: `models/server_candidates/FM_identity__identity.json`.
Три последовательных подбора, budget=1500 на стадию, seed=20261023.
Уравнения, восемь областей и 29 подбираемых параметров сохранены.
Начальные C/h определяются устойчивым покоем, а не отдельной оптимизацией.

К прежнему критерию добавлены абсолютные времена каждого пика, масштаб 1 с.
Новый train loss исходного кандидата 255.623706; после трёх попыток 172.831462.
Это другой критерий, его нельзя сравнивать со старым loss=29.030035.
Все попытки независимо пересчитаны DOP853; повторный аудит сохранённых
коэффициентов воспроизвёл все три новых train loss без изменений.
Выбор сделан только по обучению, до вычисления новых тестов.

| Набор | Средняя RMSE C, мкМ: исходный → новый | Совпадение числа пиков |
|---|---:|---:|
| Прежние 4 теста | 0.136617 → 0.111065 | 4/4 → 3/4 |
| Новые 5 тестов | 0.220473 → 0.210168 | 4/5 → 3/5 |

Физические проверки проходят во всех девяти протоколах у обеих моделей.
Однако новый кандидат **не заменяет исходную FM-модель**: улучшение средней
ошибки сопровождается дополнительными полными пиками. При tau=35 новый вариант
даёт 4 вместо 3 LR; при tau=65 — 7 вместо 6. Это не слабые затухающие максимумы
на границе порога подсчёта, а выраженные кальциевые импульсы.

Положительный эффект на времени есть: при tau=50 задержка последнего пика
уменьшилась с 3.20 до 0.55 с; при новом tau=140 — с 12.90 до 8.25 с.
При новом tau=80 и исходный, и новый кандидат дают 8 пиков вместо 7 LR.
Один штраф за время не исправил динамическую границу окончания пачки.

Для следующего эксперимента нужно контролировать прекращение колебаний при
спаде I наряду с временами пиков. Один из возможных отдельных опытов — добавить
FM разбиение по I, сохраняя постоянные региональные матрицы и точную экспоненту I.
Здесь такого изменения нет; ослабления правил числа пиков тоже нет.

Файлы:

- `summary.json`: полные метрики baseline/selected на прежних и новых входах;
- `selected/FM_identity__identity.json`: минимум нового train loss, **не принятая модель**;
- `trials/`: все три подбора, параметры, история, checkpoints и независимые оценки;
- `diagnostics/`: временные ряды LR и обоих кандидатов в NPZ;
- `FM_identity__identity_timing_comparison.png/pdf`: графики без фазового сдвига;
- `config.json`, `provenance.json`, `source_snapshot/initial`: конфигурация исходного подбора;
- `replay_config.json`, `replay_result.json` внутри попыток: независимый повторный аудит.

Первый процесс завершил три подбора, но экспорт итогов остановился из-за ошибки
создания каталога. Исправленный `--replay-trials` пересчитал уже сохранённых
кандидатов и выполнил диагностику без повторного подбора. Исходные результаты
и код расчёта сохранены, ошибка экспорта не меняла коэффициенты.

Воспроизведение и определение критерия: `docs/server_timing_refinement.md`.
