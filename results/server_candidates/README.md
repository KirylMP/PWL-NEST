# Frozen candidates returned from the laboratory server

The uploaded files are preserved byte for byte in `models/server_candidates/`.
`manifest.json` records their SHA256 hashes, source filenames and server trial
paths. Their seeds and restart indices match `source_selected_summary.json`.

Independent replay of the complete original training criterion (DOP853 for all
fixed and dynamic trajectories) reproduces the server losses:

| Case / coordinates | Server train loss | Independent replay |
|---|---:|---:|
| AM / sqrt_tails, cube | 28.1513810685 | 28.1513809192 |
| AM / sqrt_tails, log | 17.7428680388 | 17.7428680100 |
| FM / identity, identity | 29.0300348155 | 29.0300346592 |

The largest difference is 1.6e-7. `audit.json` contains the full replay groups.
The replay used the unchanged reference cache from `runs/coordinate-grid-night`;
it can also be regenerated by `prepare()` in `scripts/overnight_coordinate_grid.py`.

Several loss and validation fields inside the uploaded model metadata were
inherited from earlier fitting stages. They are historical, and are not the
current candidate's verified score. The current authoritative results are the
source summary and the independently recomputed `audit.json`, not arbitrary
`verified_*` metadata inherited by serialization. Original files are left intact.

All three remain research candidates. The current objective and waveform limits
are documented in `docs/overnight_coordinate_grid.md`. Changing the timing
criterion is a separate experiment; no old grid score or model is overwritten.
