# Подготовка AM/FM к NEST

Цель — сравнить один выбранный AM-кандидат и один исходный трёхпороговый FM-кандидат с `astrocyte_lr_1994` в NEST, с одинаковыми входными спайками, динамикой IP₃, записью и SIC. Модели с дополнительными порогами не входят в эксперимент.

## Текущее состояние

`latent_flow.py` подключает существующее отдельное C++-ядро к JSON-кандидатам этого эксперимента, преобразует C в z, вычисляет региональные аффинные коэффициенты, задаёт экспоненциальную релаксацию IP₃ и преобразует z обратно в C. `validate_latent_flow.py` сравнивает его с SciPy DOP853 на конкретном сценарии с тремя входными скачками. Это **не NEST-модуль** и **не измерение ускорения в NEST**. Требуется адаптер NEST для того же поля, времени (в NEST миллисекунды), пересечений порогов, входных событий, записи и непрерывного SIC; также необходимо сравнить траектории с LR.

По умолчанию используются серверные кандидаты `../am_two_thresholds/fits/mixed_power_fixed/candidate.json` и `../fm_four_zone_fit/candidate.json`. Другие файлы можно указать `--am` и `--fm`. Точность на одном протоколе не гарантирует нахождения всех пересечений и не подтверждает верность динамики при любых входах; native-ядро сначала выделяет пересечение конечным шагом `scan_dt`.

## Отдельное окружение NEST на сервере

```bash
bash setup_nest.sh
```

Скрипт скачивает micromamba и создаёт отдельное окружение `.nest_runtime/nest` на conda-forge с NEST 3.10, Python 3.12, GSL, CMake и компилятором. Системные пакеты не меняет; требуется интернет и место на диске. Путь можно изменить переменной `FM_NEST_RUNTIME`. Скрипт проверяет наличие `astrocyte_lr_1994` и `nest-config`. Он не устанавливает адаптер PWA, так как адаптера пока нет.

## Проверка подготовительного ядра

В Python с NumPy и SciPy и при установленном g++:

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python3 -u validate_latent_flow.py
```

Результаты будут в `results/latent_flow_validation.json`. Это промежуточная проверка и не основание заявлять выигрыш скорости в NEST.
