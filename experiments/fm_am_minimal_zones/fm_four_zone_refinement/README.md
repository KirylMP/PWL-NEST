# FM: дополнительные пороги к четырёхобластной модели

Эта серия использует исходную FM-модель с тремя порогами, включая седло; она отдельная от `fm_threshold_refinement`, где исходная модель имела два порога без седла.

| Вариант | Дополнительные фиксированные пороги | Всего порогов |
| --- | --- | ---: |
| base | нет | 3 |
| region1 | середина области 1 | 4 |
| region2 | середина области 2 (седловой) | 4 |
| region3 | середина области 3 | 4 |
| all | по одному в каждой из четырёх областей | 7 |

Области нумеруются по возрастанию C. Середина последней вычисляется между исходным верхним порогом и физической границей CMAX=2/1.185. Новые пороги фиксируются, а их положения пока не оптимизируются. Типы дочерних областей наследуют родительский: устойчивый узел, седло, неустойчивый фокус, устойчивый фокус. Новые коэффициенты при старте копируют матрицу родительской области, то есть первоначально поле остаётся тем же. У типов жёсткие ограничения по следу, определителю и дискриминанту.

Первый и третий **исходные** пороги пересекаются равновесием при фиксированных I=0.5290700389163683 и 0.8600205557570602, два коэффициента определяются аналитически. Для среднего исходного события имеется мягкая ошибка, как в прежней четырёхобластной реализации. На этапе `closed` локальная складка большого цикла задаётся численно при I=1.1231503495944923 или `FM_FIXED_FOLD_I`. Маршрут сечения определяется по найденному циклу. Локальное условие не является доказательством глобального исчезновения циклов.

## Серверный запуск

`run_all.sh` берёт исходный кандидат из `../fm_four_zone_fit/candidate.json` или пути `FM_PARENT_CANDIDATE`, переносит его параметры в `results/base/candidate.json` и затем оптимизирует базу с теми же лоссами, что и расширения. Запускайте из активированного Python-окружения:

```bash
export POINCARE_WEIGHT_SCALE=100 FM_TARGET_GRID_SIZE=10
export FM_CYCLE_COUNT_POINTS=17 FM_CYCLE_COUNT_SEEDS=32 FM_CYCLE_COUNT_WEIGHT=600
bash run_all.sh
```

Стадии расширений: `geometry`, `poincare`, `closed`. Если найденный после подготовки кандидат не подходит для инициализации складки, используется сохранённая база с точным добавлением новых областей, после чего складка проверяется заново. Если и это не удаётся, пакет останавливается. Подбор последовательный и не использует 16 ядер через WORKERS. При повторном запуске результаты перечисленных стадий могут перезаписываться; предыдущую папку `results` при необходимости сохраните.

Результаты — `results/{base,region1,region2,region3,all}/candidate.json`, логи — `logs/`, сравнение компонентов — `results/comparison.json`. Для сравнения применяйте одинаковые настройки. Путь оригинального кандидата записан в исходную подготовленную базу; дальнейший подбор может её перезаписать.

## Графики

После завершения всех вариантов:

```bash
python3 -u plot_results.py --grid-size 81 --seeds 48 --workers 16
```

Параллельный скан строит пять отдельных картинок и общую для моделей и LR; пишет путь в `results/plots/<идентификатор>/`. Завершённые точки записываются в `scan.jsonl` и повторный запуск с теми же кандидатами и настройками их использует. Значения вблизи складки и отсутствие циклов требуют более плотной независимой проверки: конечное число начальных условий не гарантирует полноту.

Код экспериментальный. Сам запуск не гарантирует нахождения физического допустимого старта складки или оптимального решения. Если он остановился, сохраните лог и последний кандидат; проверка синтаксиса не заменяет численного прогона.
