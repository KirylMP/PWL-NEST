# AM/FM с линейной координатой

Отдельная серия для AM с двумя фиксированными C-порогами и FM с тремя фиксированными C-порогами. Для обеих `z=C/0.5-1` — это только линейная нормировка физических координат; степенные, логарифмические и экспоненциальные преобразования не используются. Сами параметры поля подбираются заново.

AM применяет существующие fixed-threshold стадии `geometry`, `orbits`, `poincare`, `phase`, `closed`, `validate`. FM сохраняет исходные жёсткие региональные типы, включая седло, фиксирует пересечения первого и третьего порогов и на `closed` численно фиксирует локальную складку большого цикла. Оптимизация преобразования выключена: в FM из 18 полей вектора 4 параметра бывшего преобразования не влияют на поле и исключены из оптимизации, 2 параметра исключаются аналитически условиями равновесий, а ещё 1 — численной проекцией складки. Итого 11 свободных параметров на стадии с фиксированной складкой. Если допустимую складку найти не удаётся, скрипт прекращается с ошибкой, а последняя стадия и логи остаются на месте.

Из активированного окружения NEST 3.10:

```bash
bash run_all.sh
```

Сначала выполняются оба подбора и их независимые конечные сеточные сканирования с графиками, затем NEST benchmark на полученных `candidate.json`. Существующие кандидаты не перезаписываются. Каталог нового запуска — `results/affine_<UTC>_<случайный суффикс>/` с `am/`, `fm/`, `nest/`; его имя печатается в начале и при прерывании. Логи стадий подбора также в `../logs/`. NEST использует протокол `work-pulse`, а результаты, графики, траектории и лог NEST — в `nest/`.

По умолчанию `POINCARE_WEIGHT_SCALE=100`, `FM_TARGET_GRID_SIZE=10`, `FM_CYCLE_COUNT_POINTS=17`, `FM_CYCLE_COUNT_SEEDS=32`, `FM_CYCLE_COUNT_WEIGHT=600`, `FM_FOLD_SOLVER_MAX_NFEV=200`, `WORKERS=16`, `VALIDATE_DENSE=1`. Эти значения можно переопределять через environment, кроме закреплённого `FM_FIX_FOLD=1`. `WORKERS` ускоряет сеточную валидацию; локальные стадии оптимизации идут последовательно. Для управления сеткой FM доступны `FM_TARGET_I`, `FM_CYCLE_COUNT_I`, `FM_VALIDATE_GRID_SIZE`. Густая валидация и численная проекция складки могут занимать много времени.

NEST использует 64 астроцита на 1 потоке и 64 на 16 потоках, по 60 с модельного времени, один разогрев и три повтора. Настройки можно менять через `NEST_DURATION_S`, `NEST_VALIDATION_S`, `NEST_RESOLUTION_MS`, `NEST_SINGLE_NODES`, `NEST_MULTI_NODES`, `NEST_THREADS`, `NEST_REPEATS` и `NEST_PROTOCOL`. Для `work-pulse` длительность должна превышать 20 с. Медианы `nest.Run`, время подготовки, точность относительно независимого интегратора и RMSE по C и SIC относительно LR сохраняются отдельно. Более быстрый расчёт не доказывает достаточной точности модели.
