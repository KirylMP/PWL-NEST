# FM и AM: фиксированные C-пороги и минимальные зоны

Эксперименты на этой ветке проверяют подобранные конструкции с заранее
зафиксированными физическими порогами кальция. Порогами являются сами значения
`C_j` в мкМ; при подборе преобразования координаты `z=Phi(C)` положение
соответствующего порога в `z` пересчитывается как `Phi(C_j)`. Оптимизатор не
двигает `C_j`.

## Конструкции

| Модель | Фиксированные пороги C, мкМ | Области и ограничения |
|---|---|---|
| FM | 0.0624450437666669, 0.13693821763740716, 0.3623042888621253 | устойчивый узел → седло → неустойчивый фокус → устойчивый фокус |
| AM | 0.15880902539171288, 0.32705145045357475 | три области; региональные знаки устойчивости и положительность детерминанта заданы параметризацией |

Для FM это та же разметка восьмизонной диаграммы, сведённая к четырём
интервалам: зоны **1–4**, **5**, **6–7**, **8** соответственно. Типы задаются
по интервалам C, а не по тому, где равновесие пересекает порог при изменении I.

FM также жёстко фиксирует пересечения равновесия с первым и третьим порогом:
`I(C_1)=0.5290700389163683` и `I(C_3)=0.8600205557570602`, то есть значения
двух соответствующих переходов исходной LR. На каждом шаге аналитически
выражаются два коэффициента, чтобы `N(Phi(C_1), I_1)=H(Phi(C_1), I_1)` и
`N(Phi(C_3), I_3)=H(Phi(C_3), I_3)`. Оптимизируются 16 свободных параметров
вместо 18; два остальных вычисляются и сохраняются в полном векторе для
совместимости старого формата. Старые границы поиска этих двух вычисляемых
коэффициентов не применяются. Физичность обоих пересечений `0<h<1` проверяется
перед сохранением; промежуточное пересечение с C_2 не закреплено жёстко.

При возобновлении от старого `candidate.json` первый шаг проецирует его на
эти два ограничения: до повторного подбора форма циклов может измениться.
Ограничения задают пересечения, но сами по себе не фиксируют бифуркации и все
границы существования неустойчивых циклов или ветвей: в седловой зоне ветвь
равновесий может загибаться. При неподходящей конструкции ограничения могут
ухудшить достижимое качество fit.

Вывод граничной системы и отдельный эксперимент по совпадению складки с LR
описаны в [FM_BOUNDARY_FOLD.md](FM_BOUNDARY_FOLD.md). В финальном FM-этапе
`closed` условие складки теперь включено по умолчанию: на каждой оценке
численно решается граничная система, 15 параметров свободны и x[4] находится
из условия складки. Подготовительные этапы геометрии и начальной подгонки
используют прежние 16 свободных параметров, чтобы найти старт для `closed`.

`FM_FIXED_FOLD_I` задаёт целевой I (по умолчанию численная оценка LR
1.1231503495944923), `FM_FOLD_PROBE_I` — пробную точку для поиска начального
большого цикла (1.1), `FM_FOLD_SOLVER_MAX_NFEV` — бюджет внутреннего решателя
(120). Если заданная пробная точка не сработала, перебираются дополнительные
значения I. `FM_FIX_FOLD=0` явно отключает условие и возвращает 16 параметров.
При нерешённой граничной задаче, смене маршрута, нарушении физических границ
или невырожденности пробная точка отклоняется и не записывается кандидатом.
Если нет подходящего старта, `closed` завершается с ошибкой, сохраняя исходный
кандидат. Каждый новый лучший допустимый вариант дополнительно проверяется
интегратором DOP853 перед сохранением. Поля `fold_constraint`, `fold_constrained`,
`fixed_fold_I` и `derived_parameter_indices` есть в candidate.json; число
проекций, отказов и затраченное время есть в closed_optimizer.json и логе.

Это численное ограничение для конкретного маршрута R2,R3,R4,R3,R2,R1 и
конечной проверки его физической допустимости. Оно может не работать, если
маршрут меняется или условие плохо обусловлено; локальные проверки не доказывают
отсутствие других складок и ветвей. Оценка I_LR является численной, а не точной.

FM-папка содержит исходные данные, код и сохранённый результат четырёхзонного
подбора из `fm_four_zone_fit.zip`. У кандидата `accepted=false`: это численный
кандидат, а не доказательство минимальности или полноты найденной бифуркационной
диаграммы.

AM-папка сохраняет исходный архив с подвижными порогами для сравнения и
воспроизводимости. Новый `am_two_thresholds/fit_am.py` использует неизменные
пороги выше, 16 параметров модели (12 динамических и 4 параметра `Phi` для
смешанной координаты) и пишет результаты в `fits/mixed_power_fixed/`. Исходный
каталог `mixed_power/` остаётся только стартовым материалом: его пороги в новом
подборе не оптимизируются. Линейный сравнитель можно запускать через
`MAP_KIND=affine`; его `Phi` фиксирована, поэтому свободны только 12
динамических параметров.

## Запуск подбора

Все этапы запускаются по одному, состояние сохраняется после каждого шага, а
вывод дописывается в `logs/`. Например:

```bash
cd experiments/fm_am_minimal_zones
./run_fit.sh am geometry orbits poincare phase closed validate
./run_fit.sh fm geometry poincare orbit powell closed validate
MPLCONFIGDIR=/tmp/mplcache_fm_am XDG_CACHE_HOME=/tmp/cache_fm_am \
  OPENBLAS_NUM_THREADS=1 python3 am_two_thresholds/report_fixed.py
MPLCONFIGDIR=/tmp/mplcache_fm_am XDG_CACHE_HOME=/tmp/cache_fm_am \
  OPENBLAS_NUM_THREADS=1 python3 sweep_K_zeros.py
```

Команда принимает подмножество этапов для продолжения расчёта. Логи лежат в
`experiments/fm_am_minimal_zones/logs/`; данные этапов — в соответствующей
папке модели. AM-команды можно сопоставить с аффинной координатой:

```bash
MAP_KIND=affine ./run_fit.sh am geometry orbits poincare phase closed validate
```

В сохранённом локальном AM-проходе найдены все 9 обучающих устойчивых циклов.
RMSE крайних точек цикла — 0.00679 мкМ, периода — 0.309 с, амплитуды —
0.0116 мкМ. На сеточном аудите из 221 значения I найден максимум один цикл.
Кандидат всё ещё помечен `accepted=false`; эти числа характеризуют текущий
локальный поиск и конечную сетку. Итоговая таблица —
`am_two_thresholds/fits/mixed_power_fixed/summary.json`, рисунок —
`am_two_thresholds/fits/mixed_power_fixed/comparison_fixed_thresholds.png`.
Этот сохранённый проход предшествует добавлению ошибки сопоставления фактических
множеств равновесий в финальный `closed`; сервер пересчитывает финальный лосс.

Требуются Python 3, NumPy, SciPy, Matplotlib и `g++` для native-интегратора.
Численные остановки оптимизатора и конечная сетка сканирования циклов сами по
себе не сертифицируют глобальный минимум или отсутствие ненайденных ветвей.

## Спектральные пороги и типы равновесий при изменении K_ER

`sweep_K_thresholds.py` вычисляет физическую равновесную ветвь LR при
каждом K_ER, включая её складки, и находит изменения типа по нулям следа,
определителя и дискриминанта. Она записывает `thresholds.csv` с положениями
C и I и типами с двух сторон, `region_types.csv` с типами областей, а также
`thresholds_and_types_vs_K.png` и PDF в `results/equilibrium_types_K_sweep/`.

```bash
OPENBLAS_NUM_THREADS=1 python3 sweep_K_thresholds.py
```

Параметры сетки задаются, например, `--k-min 0.05 --k-max 0.1 --n-k 101
--n-c 3001 --i-min 0 --i-max 2`. Это спектральные переходы исходной LR при
заданном диапазоне I. Число порогов минимальной PWA-конструкции не следует
автоматически из числа переходов; выбор объединённых областей и достаточность
модели нужно проверять отдельно. Конечная сетка может пропустить близкие
переходы или касания; границы доступных интервалов C заданы сеточно.

## Равновесные нули при изменении K_ER

`sweep_K_zeros.py` независимо решает LR-равновесия через скалярную C-нулклину
на сетке `(I,K_ER)`, классифицирует каждый корень по trace, determinant и
discriminant, сохраняет таблицу CSV и строит срезы ветвей, карту числа корней и
графики `C*(K_ER)` при фиксированных `I`. Опорные режимы нанесены при
`K_ER=0.05` (FM) и `K_ER=0.1` (AM):

```bash
MPLCONFIGDIR=/tmp/mplcache_fm_am XDG_CACHE_HOME=/tmp/cache_fm_am \
  OPENBLAS_NUM_THREADS=1 python3 sweep_K_zeros.py
```

Результаты по умолчанию сохраняются в `results/equilibrium_zeros_K_sweep/`.
Можно задать более плотную сетку, например `--n-k 101 --n-i 501 --n-c 3001`.
Выполненный первичный проход использовал 36 значений K и 241 значение I;
обнаружено до трёх корней на одной точке сетки.
Это LR-семейство равновесий как функция K, а не интерполяция параметров между
подобранными AM и FM моделями. Для точного положения складок следует уточнять
их после первичного сканирования.

## Полный серверный запуск и границы реализации

На финальном этапе FM включён дискретный Poincare-штраф за лишние циклы:
на каждой точке сетки сравниваются отдельно числа устойчивых и неустойчивых
циклов кандидата и эталета. Сумма квадратов положительных превышений усредняется
по значениям I. По умолчанию сетка охватывает I=0.45–1.25 с дополнительными
точками около границ и I=1.5,2.0. Эталон — сохранённое численное перечисление
LR. `FM_CYCLE_COUNT_POINTS` (по умолчанию 17) управляет основной сеткой,
`FM_CYCLE_COUNT_SEEDS` (32) — числом высот на сечении; для построения
возвратов используются прямое и обратное время. `FM_CYCLE_COUNT_WEIGHT`
переопределяет вес, по умолчанию равный `6*POINCARE_WEIGHT_SCALE`;
вес 0 выключает этот счётчик. Лог первого вычисления показывает прогресс
по I, далее разложение и проблемные точки печатаются раз в 100 оценок.

Для точного задания небольших сеток вместо автоматических точек используйте
`FM_TARGET_I=0.55,0.8,1.0,1.1` и
`FM_CYCLE_COUNT_I=0.5,0.53,0.8,1.0,1.12,1.14,1.5,2.0`. Каждое I должно
присутствовать в файле LR_cycles_reference.json; для FM_TARGET_I там должны
быть обнаружены циклы. Дополнительные фиксированные точки не прибавляются.
`FM_VALIDATE_GRID_SIZE=41` заменяет обычную сетку независимого аудита на
равномерную из 41 точки I от 0 до 2 и имеет приоритет перед VALIDATE_DENSE
при выборе сетки I. `VALIDATE_DENSE=0` задаёт 64 высоты вместо 96 на сечение.
Редкие сетки и меньшее число высот ускоряют предварительный эксперимент,
но могут пропустить ветви и бифуркации; окончательный аудит запускайте без
`FM_VALIDATE_GRID_SIZE` с `VALIDATE_DENSE=1`.

Это дискретная ошибка корней, не сглаженный счётчик из полного протокола:
она негладкая, и поиск может пропустить близкие циклы. В JSON сохраняются
отдельные счёты, число использованных сечений и диагностика timeouts/unresolved
для кандидата и эталета. Конечное число начальных высот не доказывает
отсутствие ненайденных циклов; проверяйте результат плотным аудитом.

Вес всех этапов Пуанкаре и финальной ошибки циклов задаётся множителем
`POINCARE_WEIGHT_SCALE` (по умолчанию 1). Например:

```bash
POINCARE_WEIGHT_SCALE=5 WORKERS=8 bash run_server.sh
```

При значении 5 финальные веса циклов составляют 10 для AM и 30 для FM
вместо 2 и 6. Множитель применяется к сумме квадратов ошибок, а не к самим
остаткам; геометрия, спектр и равновесия не масштабируются. При отсутствии
целевого цикла соответствующий штраф также усиливается. Подготовка по полю
на орбитах LR остаётся с прежними весами. Активный множитель выводится при
старте этапа и сохраняется в JSON кандидата. Финальные кандидаты также
содержат `loss_components`: геометрия, фактические множества равновесий,
сырая и взвешенная ошибки циклов и полная ошибка.

Для дополнительного уточнения уже сохранённых кандидатов можно выполнить
только `closed validate`, затем соответствующий отчёт. Настройки читаются
при старте Python-процесса; текущий работающий процесс их не подхватит.

В FM используются сохранённые эталонные циклы на приблизительно равномерной
сетке от I=0.53 до I=1.12, дополненной шестью исходными точками. Размер сетки
задаётся `FM_TARGET_GRID_SIZE` (по умолчанию 25); точки привязываются к
ближайшим сохранённым значениям LR, где найден хотя бы один цикл. В лосс
входят найденные устойчивые и неустойчивые орбиты. Остатки умножаются на
sqrt(9/число целевых орбит), чтобы при изменении сетки вес средней ошибки
орбиты оставался сравнимым с первоначальным набором из девяти орбит.

Можно дополнительно включить поиск лишних циклов при I=1.5 и I=2.0, где в
эталонном наборе LR циклы не обнаружены, и добавить штраф
`FM_EXTRA_CYCLES_WEIGHT * (N(1.5)^2 + N(2.0)^2)`; по умолчанию вес 0.
Счёт включает устойчивые и неустойчивые циклы. Это конечный поиск по 32
начальным высотам на каждом равновесном сечении: он может пропустить циклы,
а его целочисленный штраф негладкий. Более плотный аудит следует после fit.
Штраф независимо задаётся через `FM_EXTRA_CYCLES_WEIGHT`, а не через
`POINCARE_WEIGHT_SCALE`. Эти точки повышают стоимость каждой оценки лосса.
Сетку можно задать строкой `FM_NO_CYCLE_INPUTS=1.5,2.0`: каждая точка должна
точно присутствовать в LR_cycles_reference.json и не содержать найденных
циклов. Число найденных лишних циклов и диагностика поиска пишутся в лог и JSON.

`bash run_server.sh` запускает AM и FM параллельно, проходит все этапы подбора,
аудит и отчёты с отдельной проверкой орбит DOP853, затем сканирует LR по K.
По умолчанию каждый аудит использует 8 процессов (суммарно до 16 для двух
режимов); оптимизаторы внутри одного старта работают последовательно.
Логи этапов находятся в `logs/`, сводный stdout можно направить в
`logs/server.log`. Для воспроизведения сохраняется `logs/server_environment.txt`.

Это полный запуск **нового протокола из обсуждения с фиксированными зонами**:
геометрия/спектр и равновесные якоря → поле на орбитах LR → подготовка возвратами
→ финальная ошибка на настоящих корнях Пуанкаре → независимый сеточный аудит.
В финальном `closed` дополнительно сопоставляются фактические множества
равновесий на 25 значениях I: квадрат расстояния с масштабами 0.05 мкМ и
0.05 для h, штраф 25 за отсутствующий или лишний корень. FM включает прямые
устойчивые и обратные неустойчивые возвраты. AM включает устойчивые целевые
циклы; лишние устойчивые и неустойчивые циклы ищутся отдельным аудитом.

Приложенный `FM_REDUCTION_PROTOCOL.md` также содержит прежний протокол с
обучением сглаженного числа циклов, аналитические разделы и исследование
сложности. Сглаженный счётчик, доказательство минимальности, автоматический
выбор конструкции и бенчмарк NEST в `run_server.sh` не входят. Пороги и
конструкции уже выбраны до серверного подбора. Конечный аудит перечисления
ветвей остаётся численным и может пропускать малые или близкие циклы.
